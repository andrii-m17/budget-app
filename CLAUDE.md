# CLAUDE.md — Бюджет-локально

Інструкції для Claude Code, коли він працює в цьому репозиторії
(`andrii-m17/budget-app`, deploy на GitHub Pages: `andrii-m17.github.io/budget-app`).

## Що це за проєкт

Особистий Ukrainian-мовний PWA для ведення сімейного бюджету (Андрій + Оля).
Один основний файл `index.html` (весь UI + бізнес-логіка + localStorage),
`sw.js` (service worker для офлайну), `manifest.json`, `icons/`.

## Обов'язкова дисципліна ревізій — НЕ порушувати

1. **Одна ревізія = одна ізольована, скопована зміна.** Не змішувати кілька
   не пов'язаних правок в одному коміті/Rev.
2. **Кожен реліз піднімає версію в ДВОХ місцях одночасно:**
   - `const CACHE_NAME = 'budget-app-vX.Y.Z';` у `sw.js`
   - текст версії у футері `index.html` ("Rev X.Y.Z")
   Якщо забути підняти `CACHE_NAME` — вже встановлені PWA не побачать оновлення
   (service worker роздає стару закешовану версію).
3. **Коментар над кожною суттєвою зміною в коді** — що змінено, чому, які
   ризики/альтернативи розглядались. Дивись стиль існуючих коментарів
   (`// Rev 2.11.22 — Mobile Zoom: ...`) і продовжуй той самий формат.
4. Перед пропозицією "нового" фіксу — обов'язково звірити з `docs/ROADMAP.md`,
   розділ "матриця вже випробуваного" (особливо для iOS status-bar бага) —
   там явно зафіксовано, що вже пробували і чому не спрацювало. Не пропонувати
   повторно те, що вже в цій таблиці.
5. Тестування на реальному iPhone вважається обов'язковим кроком перед тим, як
   вважати Rev "завершеним" — я (модель) не можу цього зробити сама, тому явно
   позначай у відповіді, що саме користувачу треба перевірити на пристрої.

## Відомі платформні обмеження (не намагатись "полагодити" без нових фактів)

- **iOS 26 WebKit Bug 301108** — при зміні теми з `black-translucent`/`black`
  status-bar-style неможливо одночасно отримати (а) колір статус-бару під тему
  і (б) коректну геометрію знизу. Поточний компроміс: `status-bar-style: default`.
  Деталі й повний список випробуваного — `docs/ROADMAP.md`.
- **Спалах `env(safe-area-inset-top)` при `orientationchange`** — при
  поверненні з альбомної в книжкову орієнтацію відступ заголовка (`.top`)
  на ~0.2с зникає (контент притискається до статус-бару), потім
  відновлюється. Підтверджено (6D.120, `docs/ROADMAP.md`) живим тестом на
  iPhone з повністю вимкненим `scrollTo(0,0)` — спалах лишався так само,
  тобто це НЕ побічний ефект коду фіксу клікабельності таббару (Баг 1,
  `fixStuckVisualViewportOffset()`), а незалежна поведінка iOS/WebKit.
  Дві спроби замаскувати цей спалах (`visibility:hidden`, 6D.110;
  position:fixed-оверлей, 6D.115-118) провалились структурно — елемент-
  маска сам підпадає під ту саму нестабільність. Без нового підходу до
  самого `env(safe-area-inset-top)` — не повторювати ці дві техніки.
- **Системний edge-резерв WKWebView для лівого/правого краю екрана** —
  дотики, що починаються в межах приблизно перших ~15-20px від фізичного
  краю екрана, спершу перехоплюються власним системним edge-swipe-
  розпізнавачем iOS (interactive pop gesture recognizer) і не доходять до
  `touchstart` веб-сторінки взагалі (чи доходять спотворено) — підтверджено
  живим тестом (6D.133, `docs/ROADMAP.md`): у цій смузі власний
  edge-swipe-закриття Журналу (Rev 2.19.1+) не спрацьовував, хоча код
  технічно мав це покривати. Жодного надійного CSS/JS-способу обійти цю
  системну зону немає — будь-яка власна "зона старту жесту від краю"
  (`EDGE_ZONE`-подібні константи) реально працює лише ПОЧИНАЮЧИ з кінця
  цієї системної смуги, ніколи від буквального 0.
- **iOS QuickType-панель "Автозаповнити контакт" над клавіатурою** — для
  поля "Назва витрати" зʼявлялась системна панель передбачення тексту з
  пропозицією контакту. **ВИПРАВЛЕНО (6D.136-141, Rev 2.22.65-70)** —
  підтверджено 4 послідовними живими тестами на iPhone (ізольоване
  тестування кожного прийому окремо). Причина й фікс виявились
  найпростішими з можливих: САМ підрядок "name" в `id` поля (було
  `id="f-name"`). Єдина потрібна зміна — абстрактний `id` без "name"
  (тепер `id="expfielda7"`). `autocomplete="one-time-code"` (здавалось
  необхідним у 6D.136) і `readonly`-до-фокуса — ОБИДВА підтверджено
  зайві (6D.140-141) — жодного стосунку до цього симптому не мали. CSS
  `::-webkit-contacts-auto-fill-button` (6D.134) теж прибраний — цілив в
  інший, не пов'язаний UI-елемент. Спроби 1-4 з самого початку
  (`autocomplete="off"`, нестандартне значення з дефісами, прибраний
  `<label for>`) також не спрацювали самі по собі. Якщо колись
  знадобиться перейменувати поле назад на щось "name"-подібне — підказка
  повернеться, це перевірений факт, не здогадка.
- **Стандартна iOS-панель "Попереднє/Наступне/Готово" над клавіатурою**
  (сірий тулбар зі стрілками ‹ › і галочкою) — залишається порожньою
  (без підказки) навіть після 6D.136, і це ОКРЕМЕ від автозаповнення
  явище: штатна функція WKWebView/Mobile Safari для навігації між полями
  форми, офіційно не вимикається для звичайної (не-нативної) веб-
  сторінки/PWA — підтверджено (Apple Developer Forums, обговорення
  "cannot be removed... in native Safari browsing" навіть в останніх
  версіях iOS). Єдиний задокументований хак (`inputmode="none"→"text"`
  на фокусі) прямо позначений автором як ненадійний і з ризиком, що
  клавіатура іноді взагалі не з'явиться — свідомо НЕ застосовано за
  рішенням користувача (ризик для основної функції важливіший за
  косметику порожньої панелі). Прийнято як платформне обмеження.

## Правила для текстових полів вводу (iOS «Автозаповнити контакт»)

**Текстові поля вводу не повинні викликати панель iOS «Автозаповнити контакт».** У `id` і `name` будь-якого текстового поля (`input` типів text/search/tel/email/number/password, `textarea`) ніколи не використовувати підрядки `name`, `phone`, `tel`, `mail`, `addr`, `user`, `login`, `first`, `last`, `fio`, `contact` (без урахування регістру). Усі нові й перейменовані поля мають абстрактні id за схемою `fld` + код + число (наприклад `cddfielda1`, `edtfielda1-<id>`). Не покладатися на `autocomplete`, `readonly`, `<label for>`: у 6D.132–141 (`docs/ROADMAP.md`) доведено, що вирішальний лише `id`. Охоронний тест `tests/input-attrs.test.js` перевіряє всі поля (розмітка, JS-шаблони, динамічні) і фіксує їх інвентар — нове поле змушує свідомо оновити перелік. Про кожне нове поле (або перейменування) згадувати в записі ревізії. Діагностика при поверненні панелі: «Запис діагностики» → торкнутися поля → «Мітка» → подія `input-focus-audit`.
