# E2E-1: перевірка основних сценаріїв у WebKit

Мета: автоматично ловити поломки розкладки й основних сценаріїв у WebKit (рушій Safari), щоб менше перевіряти вручну на iPhone. Це доповнення до `node --test`, не заміна: реальний iPhone лишається обов'язковим для завершеності Rev.

## Як запускати
```
npm install            # один раз (devDependency @playwright/test)
npx playwright install webkit   # один раз, завантажує браузер WebKit
npm run e2e            # ≈ 20–25 с; один повтор при збої; ліміт усього запуску 3 хв
```
- Не входить у `pre-push-guard` і в `npm test` (`node --test` файлів `e2e/` не бачить).
- Знімки лише при падінні: `e2e-results/<мітка часу>/` (теку ігнорує git). Еталонних знімків немає, пікселі не порівнюються.
- Один сценарій: `npx playwright test -g "конфлікт"`; лише темна тема: `--project=dark`.

## Середовище
- Сервер: `e2e/server.js` (статичний, без залежностей, порт 8935, змінна `E2E_PORT`). Службовий воркер заблоковано.
- Пристрій: iPhone 14 (390×844) у WebKit; проєкти `dark` (усі 10 сценаріїв) і `light` (лише сценарії з міткою `@both`: 1, 2, 8).
- Cloud: вбудований мок `dev/mock-cloud.js` (`?fixture=empty`), у робочу базу нічого не пишеться. Мережу емульовано в сценаріях прапорцем `window.__offline` у `MockCloud.fetch` (+ `navigator.onLine`), затримку відповіді — `window.__delay`.
- «Другий пристрій» — `MockCloud.otherDevice(...)`: змінює стан сервера й емітить подію, як справжній Realtime. Окремих двох браузерних контекстів немає, бо кожен контекст має власний мок в пам'яті.

## Що покрито (10 сценаріїв)
1. Старт із порожніми даними: усі п'ять вкладок, без помилок JS і горизонтального скролу.
2. Додати витрату через форму: з'являється в списку й на сервері.
3. Відредагувати витрату: нова сума локально й на сервері.
4. «Перевірки»: «Працює» і «Не працює» з причиною (стан у `checksReadState`).
5. Без мережі: додати витрату → індикатор `pending`; повернення мережі → `done` → слот порожній; запис на сервері.
6. Конфлікт того самого поля (офлайн-правка, «інший пристрій» змінює суму): картка конфлікту, «Повернути моє» → моя сума локально й на сервері.
7. Поле вводу з фокусом: картка конфлікту не з'являється, поки фокус у полі, і з'являється після його втрати.
8. «Платежі»: закрита й прихована (за `installment:#id`) ОЧ не показуються, відкрита показується.
11. «Перевірки», спільний список сім'ї (два контексти): відповідь одного ховає крок у другого після його оновлення, «Не можу перевірити» не ховає, числа однакові. Номер 11, бо 9–10 зарезервовано під сценарії доходів і боргів.
33 пошук журналу: 0 змін DOM поза списком під час набору. 32 тап по push позначає сповіщення прочитаним (push_id, група, холодний старт, офлайн-черга, невиконаний перехід не позначає). 31 поля пошуку: нейтральні підказки, type=search. scenarios 12 слова: різні рішення, сервер переміг (±1 доба), видалення проти правки, обоє створили слово, відновлення при живому, висячий cloudId, без зліпка, порожній push. scenarios 11 приховані: обоє приховали (годинник ±1 доба), приховав/показав, рядок зник на сервері, запис без зліпка, старий ключ, повторне приховування без змін. 30 збереження без змін: 0 записів на сервер, updatedAt/localRev незмінні (витрата, дохід, картка, ОЧ, категорія). 29 «Конфлікти» у журналі сповіщень: свайп видаляє оброблений, необроблений з підтвердженням, «Очистити» лишає необроблені, лічильник дзвіночка. 28 живий DOM: усі поля (крім входу) autocomplete=off, без тире й тригерів у name/id. 27 діагностика полів: fields-snapshot (start/mark/stop), field-added для fldstr3 у «Словнику», без значень. 26 підказки в редагуванні запису: рядок у DOM після blur, поки триває дотик; вибір за ≈ 150 мс без pointerup; тап по «Сумі» < 150 мс. 23–25 (файл `e2e/taps.spec.js`): матриця тапів < 150 мс і один раз, зони дотику 44 пт без перекриття, підказки не видаляються під пальцем. 22 після вставки підказки (touchend не прийшов): тап по полю назви, «Сумі», кнопці з першого дотику < 150 мс. 21 підказка без touchend: тап за 150 мс, рух > 8 px не обирає, без дублів. 20 підказка назви: 0 перемальовувань при незмінному тексті, вибір < 150 мс, фокус на «Суму». 19 без мережі: плашки нема, нічого не зсувається (також при відкритій клавіатурі), індикатор біля аватара на всіх вкладках, «Потрібна мережа» біля «Синхронізувати зараз». 17 швидкий запит: після `pending` і при кожній відправці `syncing` (не менше `SYNC_MIN_SYNCING_MS`, рівно 3 блимання) → `done`; повторна правка під час `syncing` не перезапускає анімацію. 18 відкрита клавіатура (емульований `kb-open`): конфлікт не зсуває екран і не перемальовує список.
12–16 (файл `e2e/push-tap.spec.js`, Rev 2.32.203): тап по push. 12 холодний старт `installment-deadline` з одним `installmentId` (перехід, підсвітка переживає перемальовування, знімається за 3 с); 13 `installmentIds` списком і без id (лише перехід); 14 теплий старт (повідомлення від service worker); 15 Monobank, холодний старт при повільній мережі («Вхідні» одразу); 16 Monobank, теплий старт із підсвіткою пачки. «Холодний старт» = перезавантаження сторінки з параметрами push і даними в локальному сховищі; затримка мережі моку — `localStorage.__lat`, підключений Monobank із двома новими операціями — `localStorage.__mono`.
9. Доходи: різні поля зливаються мовчки (моя сума офлайн, чуже джерело), без сповіщень.
10. Борги: те саме поле дає картку конфлікту з назвою запису й «Повернути моє».

## Нотатки
- Сценарій 5 ловить стани індикатора спостерігачем мутацій (`done` триває ≈ 1 с, опитування його пропускає). Штучна затримка (`window.__delay`) застосовується лише до записів витрат: інакше початкова синхронізація довідників (десятки POST) розтягувалась і давала нестабільність.
- Розбіжність, знайдена E2E-1 (`syncing` не показувався після повтору з `pending`), виправлена в Rev 2.32.200; тепер сценарій перевіряє послідовність `pending → syncing → done`.

## Правила розвитку
Не більше десяти сценаріїв без рішення чату; без перевірок пікселів; еталонні знімки в репозиторій не додаються.
