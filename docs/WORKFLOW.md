# Протокол роботи: Андрій · Чат (claude.ai) · Claude Code

## Ролі
| Хто | Відповідає за |
|---|---|
| **Андрій** | рішення, перевірка на iPhone, передача промтів і звітів |
| **Чат** | продукт і дизайн, макети, специфікації (промти), **усі зміни сервера Supabase** (міграції, функції, cron) з тестами в транзакції, аналіз даних і логів, приймання звітів |
| **Claude Code** | Крок 0, реалізація клієнта, тести, перевірка в preview, скріншоти, `docs/ROADMAP.md`, `docs/STATUS.md`, `docs/UI_PATTERNS.md` |

## Класи ризику
| Клас | Приклади | Процес |
|---|---|---|
| **A** (низький) | тексти, кольори, відступи, стилі без логіки | реалізація → тести → скріншоти → звіт |
| **B** (середній) | нова функція інтерфейсу, логіка без зміни даних | короткий Крок 0 у тому ж запуску → реалізація → субагент `spec-reviewer` → звіт |
| **C** (високий) | клавіатура iOS, синхронізація, дані й міграції, безпека, фінансові правила | **лише Крок 0** (режим плану) → підтвердження чату → реалізація → `spec-reviewer` → перевірка на iPhone + лог діагностики |

## Цикл задачі
1. **Запит** (Андрій) → 2. **Факти** (чат перевіряє дані через Supabase лише читанням) → 3. **Макет** для UI (чат) → 4. **Промт** за шаблоном `prompts/TEMPLATE-task.md` → 5. **Крок 0** для B/C → 6. **Реалізація** + самоперевірка → 7. **Звіт** (`task-report`) → 8. **Приймання** чатом (звірка з макетом і ТЗ, перевірка сервера) → 9. **iPhone** за `qa.json` → 10. **STATUS** оновлено.

## Готовність (Definition of Done) для кожного Rev
- [ ] `node --test` зелений (гачок перевіряє перед `git push`).
- [ ] `APP_VERSION` і `CACHE_NAME` узгоджені; запис у `docs/ROADMAP.md`; тег `rev-<версія>`.
- [ ] UI: скріншоти «після» в обох темах, ширина 390 і 440; відхилення від макета перелічені.
- [ ] Продуктивність і запити: виміряно до/після, якщо задача про це.
- [ ] Жодного запису в робочу базу з preview чи тестів.
- [ ] Клас C: пункти перевірки на iPhone додано в `qa.json`.
- [ ] `docs/STATUS.md` оновлено; звіт за `task-report`.

## Економія ресурсів Claude
- **Чат:** вищі модель і зусилля для дизайну, архітектури, аналізу даних і логів; звичайні для приймання звітів і дрібних промтів. Нова розмова на кожну велику тему; стан береться з `docs/STATUS.md` (завантажувати в Project після змін).
- **Claude Code:** `/plan` (режим плану) для Кроку 0; `/effort` вищий лише для класу C; `/clear` між задачами; `/compact` у довгих сесіях; правила живуть у навичках, тому промти коротші.
- **Промти посилаються на навички**, а не повторюють загальні правила.
- **Один звіт = один формат**: менше читати, менше уточнень.

## Відкат
`git revert <коміт>` → новий Rev (нові `APP_VERSION`/`CACHE_NAME`) → push. Ніколи не `push --force` у `main`. Теги `rev-*` показують, до чого повертатись.
