# Протокол роботи: Користувач А · Чат (claude.ai) · Claude Code

## Ролі
| Хто | Відповідає за |
|---|---|
| **Користувач А** | рішення, перевірка на iPhone, передача промтів і звітів |
| **Чат** | продукт і дизайн, макети, специфікації (промти), **усі зміни сервера Supabase** (міграції, функції, cron) з тестами в транзакції, аналіз даних і логів, приймання звітів |
| **Claude Code** | Крок 0, реалізація клієнта, тести, перевірка в preview, скріншоти, `docs/ROADMAP.md`, `docs/STATUS.md`, `docs/UI_PATTERNS.md` |

## Класи ризику
| Клас | Приклади | Процес |
|---|---|---|
| **A** (низький) | тексти, кольори, відступи, стилі без логіки | реалізація → `node --test` → звіт (без знімків і субагентів) |
| **B** (середній) | нова функція інтерфейсу, логіка без зміни даних | реалізація → звіт (Крок 0 лише коли в ТЗ є відкриті рішення; `spec-reviewer` не потрібен) |
| **C** (високий) | клавіатура iOS, синхронізація, дані й міграції, безпека, фінансові правила | Крок 0 і зупинка **лише коли в ТЗ є відкриті рішення** (режим плану) → реалізація → `spec-reviewer` лише для даних, синхронізації чи безпеки → перевірка на iPhone лише того, що не перевіряється автоматично |

## Цикл задачі
1. **Запит** (Користувач А) → 2. **Факти** (чат перевіряє дані через Supabase лише читанням) → 3. **Макет** для UI (чат) → 4. **Промт** за шаблоном `prompts/TEMPLATE-task.md` (ТЗ пише чат у відповіді; Користувач А вставляє в Claude Code; Notion не використовується) → 5. **Крок 0** для B/C → 6. **Реалізація** + самоперевірка → 7. **Звіт**: повний у `docs/reports/<код>.md`, чату короткий (`task-report`) → 8. **Приймання** чатом (звірка з макетом і ТЗ, перевірка сервера) → 9. **iPhone** за `qa.json` → 10. **STATUS** оновлено.

## Звіти (схема без Notion)
- Notion для звітів і статусів не використовується: Claude Code його не читає й не пише. Винятки: специфікації відкритих задач, що вже лежать у Notion (NOTIF-3, NOTIF-1 Rev 4, PAGING-1 Rev B, NOTIF-2), Claude Code лише читає, поки їх не перенесено.
- Повний звіт: `docs/reports/<код>.md` (формат `task-report`), іде в коміт.
- Чату: короткий звіт: стільки, скільки потрібно для рішення, без повторення контексту (класи A і B ≈ до 25 рядків, клас C і дослідження ≈ до 60): зроблено, тести, відхилення, відкриті питання, чи запушено.
- Публікація: клас A (без змін вигляду, даних, синхронізації) Claude Code публікує сам після тестів і повідомляє; класи B і C лише після «можна пушити» в чаті. Зміни вигляду лише за макетом, який погодив власник. Розробницька діагностика лише за перемикачем, вимкненим за замовчуванням. Специфікації відкритих задач лежать у `docs/specs/<код>.md`.

## Автотести синхронізації на тестовому сервері (E2E-CLOUD, Rev 2.32.243)
- Для класу C, що зачіпає синхронізацію (push/pull, ідентичність записів, міграції), прогін `npm run e2e:cloud` обов'язковий: справжній тестовий проєкт Supabase, два браузерні контексти («Тест А», «Тест Б»), кількість рядків перевіряється REST-запитом. Лише локально, у CI не запускається.
- Потрібен `.env.test` (у `.gitignore`; зразок `.env.test.example`): адреса й публічний ключ тестового проєкту та email/пароль обох тестових користувачів заповнює власник. Робочу базу набір не бачить: прогін зупиняється, якщо адреса не тестового проєкту. Деталі: `docs/E2E.md`.

## Кроки «Перевірок» на пристрої (Rev 2.32.245)
- Лише для того, що не перевіряється автоматично: клавіатура (до появи SIM-1), push, реальна мережа. Синхронізацію «два пристрої» (ідентичність, перейменування, дублі) перевіряє `npm run e2e:cloud`; кроків на телефоні для неї не додавати (2.32.242-1/2 і 2.32.244-1/2 прибрано).

## Клавіатура, листи й форми на симуляторі (SIM-1)
- `npm run e2e:ios` (Appium + XCUITest, Safari на симуляторі iPhone й iPad, портрет і ландшафт; ≈ 3 хв) **більше не обов'язковий (рішення чату, Rev 2.32.259): запускати лише на прямий запит чату**; для клавіатури достатньо `node --test` і клавіатурних E2E на WebKit. Результат у `docs/ui/sim/<версія>/summary.md`. Опис, пороги, розбіжність «вкладка Safari / PWA» і обмеження: `docs/E2E-IOS.md`. Прогін іде в PWA (веб-кліп localhost на симуляторі); часові метрики порівнюються з еталоном `docs/ui/sim/baseline.json` (оновлювати `SIM_UPDATE_BASELINE=1` лише після перевірки). Справжні знахідки (див. розбір у `docs/E2E-IOS.md`) підтверджує власник на телефоні.

## Перевірка за ризиком (економія часу й токенів; рішення власника 22.10.2026)
| Клас | Автотести | Знімки | Субагенти |
|---|---|---|---|
| **A** | `node --test` | немає | немає |
| **B** | `node --test` | один знімок «до/після» зачепленого екрана, темна тема, 390 pt; попіксельне «0» лише для змін, які мають бути невидимими | немає |
| **C** | `node --test` + цільові сценарії на моку | немає, якщо немає зміни вигляду | `spec-reviewer` один раз, лише для даних, синхронізації чи безпеки |
- `apple-review` і навичка `apple-pwa-design` лише на запит власника.
- **Знімки (лише вони, не автотести, збірка чи гачок пушу):** один ланцюжок за раз; кожен запуск пише у власну теку з міткою часу (ніколи в ту саму теку з кількох запусків); готовність = код завершення процесу, а не перегляд журналу чи файлів; ліміт 60 с на знімок і 3 хв на весь крок; при перевищенні одна повторна спроба лише для знімка, що не вдався, далі йти далі, а у звіті написати «знімок X не отримано, причина Y»; якщо знімки не вдалися двічі поспіль, не повторювати, а запропонувати у звіті вимкнути їх для цієї задачі. «Не завершено» стосується лише знімків, не задачі: задачу це не блокує.
- Автотести, збірка, гачок пушу: таймерів не застосовувати, чекати завершення.
- Скрипти порівняння (`scripts/tap-targets.mjs`, `scripts/notif-history-shots.mjs`) необов'язкові: запускаються лише за прапорцем `--run` (інакше друкують довідку й виходять).

## Економія ресурсів Claude
- **Чат:** вищі модель і зусилля для дизайну, архітектури, аналізу даних і логів; звичайні для приймання звітів і дрібних промтів. Нова розмова на кожну велику тему; стан береться з `docs/STATUS.md` (завантажувати в Project після змін).
- **Claude Code:** `/plan` (режим плану) для Кроку 0; `/effort` вищий лише для класу C; `/clear` між задачами; `/compact` у довгих сесіях; правила живуть у навичках, тому промти коротші.
- **Промти посилаються на навички**, а не повторюють загальні правила.
- **Один звіт = один формат**: менше читати, менше уточнень.

## Відкат
`git revert <коміт>` → новий Rev (нові `APP_VERSION`/`CACHE_NAME`) → push. Ніколи не `push --force` у `main`. Теги `rev-*` показують, до чого повертатись.
