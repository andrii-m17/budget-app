# STATUS.md — Бюджет-локально, стан проєкту

Чекпоінт: 2026-08-27
Файл-джерело поточної реалізації: пакет `index.html` + `manifest.json` + `sw.js` + `icons/`
(Rev 2.3.5). З Rev 2.3.3 застосунок перестав бути одним файлом — повноцінний PWA
(service worker, офлайн-доступ, «Додати на головний екран») технічно вимагає окремих
файлів маніфесту й service worker. `index.html` лишається головним і найбільшим файлом,
решта — обслуговуючі, деплояться разом.
Файл-еталон дизайну: `PROJECT_SPEC.md` (синхронізовано цього ж дня — попередня версія
описувала Rev 2.1.39 і відставала на дві ревізії, 2.2.x і 2.3.x).
Бізнес-логіка: `FINANCIAL_RULES_AND_OBLIGATIONS_v1.md` (актуальний, без змін).

Розгорнуто на GitHub Pages — до Rev 2.3.3 застосунок відкривався лише як локальний
файл (`file://`), що технічно не сумісне з service worker.

### Rev 2.2.0 — Модель ОЧ (очікуваний/фактичний залишок) + автозв'язок витрата↔ОЧ
- **2.2.0** — pre-fill поля «Залишок» ОЧ з попереднього факту (той самий принцип, що вже
  діяв для карток)
- **2.2.1** — очікуваний залишок = попередній факт − статистична мода історичних платежів
  (не останнє значення — стійкість до одноразових аномалій); вибіркове збереження рядків:
  недоторканий рядок лишається незбереженим, а не мовчки фіксується фактом
- **2.2.2** — Метод C автозв'язку (двоетапний пошук: повний збіг назви пріоритетний над

  вибору); Метод B (кнопка «Оплатити цю ОЧ» → форма витрати з готовою прив'язкою); сума
  прив'язаної витрати переважає статистичну оцінку для очікуваного платежу
- **2.2.3** — тихий тег «не збережено» в Обліку (борги/ОЧ); захист від втрати незбережених
  змін при зміні місяця чи вкладки (окремий dirty-стан для банків і ОЧ, підтвердження
  переходу через кастомну модалку)

### Rev 2.3.x — Щоденне використання (бекап, чернетка, PWA, автофокус, автопідказка)
- **2.3.1** — повний бекап/відновлення всього стану застосунку одним JSON-файлом (окремо
  від часткового Excel-експорту, який лишається проекцією для основного файлу Андрія);
  валідація тегом `__budgetBackup`; відновлення повністю замінює поточні дані з
  підтвердженням через кастомну модалку
- **2.3.2** — автозбереження чернетки форми «Нова витрата»: не втрачається при
  випадковому закритті вкладки/браузера до натискання «Додати»; автоматичне очищення
  одразу після успішного збереження запису; скидання дати на «сьогодні» при вході на
  вкладку більше не спрацьовує, якщо є незбережена чернетка
- **2.3.3** — PWA: `manifest.json` + `sw.js`, іконки 192/512/apple-touch-icon (той самий
  «тренд угору», що в лого застосунку); офлайн-кеш (мережа-спочатку для самого HTML —
  щоб онлайн завжди підхоплювалась найсвіжіша версія, кеш-спочатку для решти); «Додати
  на головний екран»; розгорнуто на GitHub Pages
- **2.3.4** — автофокус на «Назва витрати» при вході на вкладку «Витрати» (виклик
  синхронний, без `setTimeout` — критично для iOS Safari, де клавіатура відкривається
  програмним `focus()` лише в межах того самого жесту користувача); якщо форма вже
  заповнена з відновленої чернетки — фокус розумно йде одразу на «Суму»
- **2.3.5** — автопідказка назви витрати за історією введень (не за словником
  автокатегоризації): власний DOM-компонент замість нативного `<datalist>` (той
  ненадійний на iOS Safari — часто взагалі не показує спадний список); підрядковий
  пошук (не лише з початку слова), сортування за частотою+свіжістю; вибір підказки
  підставляє категорію з реальної історії саме цієї назви (точніше за загальне ключове
  слово словника)

## Технічна нотатка: структура файлів (з Rev 2.3.3)

Застосунок більше не одне ціле — деплой на GitHub Pages вимагає такої структури в
корені репозиторію:
```
index.html
manifest.json
sw.js
icons/
  icon-192.png
  icon-512.png
  apple-touch-icon.png
```
При кожному новому релізі: (1) оновити `index.html`, (2) обов'язково підняти версію
константи `CACHE_NAME` у `sw.js` — інакше вже встановлені PWA не побачать оновлення
(service worker роздає стару закешовану версію, доки версія кешу не зміниться).
