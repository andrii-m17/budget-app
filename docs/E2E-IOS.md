# SIM-1/SIM-2: автотести клавіатури й форм у PWA на симуляторі iOS

Мета: перевіряти екранну клавіатуру iOS без телефона, саме в режимі PWA (веб-застосунок із головного екрана), яким користується власник. Лише інструменти: `index.html`, `sw.js`, `kb-*`, `inert`, фокус і формули не змінюються.

## Запуск
```
npm install                     # один раз (devDependencies: appium, webdriverio)
APPIUM_HOME=$PWD/.appium npx appium driver install xcuitest   # один раз (тека .appium у .gitignore)
npm run e2e:ios                 # усі чотири конфігурації, 3 прогріті проходи на сценарій + холодний, ≈ 8 хв
SIM_ONLY=iphone-portrait SIM_REPS=1 npm run e2e:ios   # одна конфігурація (iphone-portrait, iphone-landscape, ipad-portrait, ipad-landscape), швидко
SIM_UPDATE_BASELINE=1 npm run e2e:ios                  # зафіксувати еталон симулятора для поточної версії
```
- Потрібні Xcode і симулятори (`iPhone 16 Pro Max`, `iPad (10th generation)`; змінні `SIM_IPHONE`, `SIM_IPAD`). Сам запускає статичний сервер (`e2e/server.js`, порт 8937) і Appium (порт 4723) і зупиняє їх.
- Код виходу 1, якщо хоч один сценарій не пройшов. У `pre-push-guard` не входить.

## Яка PWA запускається
- На симуляторі має бути веб-кліп з адресою **`http://localhost:8937/index.html`** (Safari → «Поділитися → На початковий екран»). Автомат знаходить такий кліп у `~/Library/Developer/CoreSimulator/Devices/<udid>/data/Library/WebClips`, дає йому назву «Money Tree Sim» (щоб відрізнити від кліпа GitHub Pages, обидва зазвичай «Money Tree») і перезапускає SpringBoard.
- Після запуску адреса в сторінці перевіряється: якщо це не `http://localhost:8937/…`, прогін зупиняється (`ЗУПИНКА`). Іконки з GitHub Pages ніколи не запускаються.
- Стан на момент SIM-2: на обох симуляторах поруч є другий кліп «Money Tree» з адресою GitHub Pages (в автотестах не використовується; бажано видалити, щоб не переплутати). Кліп з локальною адресою був уже встановлений.
- Без кліпа прогін зупиняється з інструкцією встановити його.

## Як це працює (чому PWA автоматизується)
- Appium-сесія на SpringBoard (`com.apple.springboard`): звідти доступні іконки, знімки екрана й дотики. Іконку «Money Tree Sim» запускає дотик (гортання домашніх екранів); PWA з'являється як контекст `WEBVIEW_*`, у якому працює звичайний JS (`navigator.standalone === true`).
- **Фокус ставиться справжнім дотиком** (`mobile: tap` у NATIVE_APP). Координати: прозорий шар у сторінці ловить два реальні дотики у відомих точках екрана, з їхніх `clientX/clientY` рахується масштаб і зсув (один раз на завантаження, клавіатура закрита).
- Лист відкривається викликом застосунку (`openCardDebtEditor`, `showProfileLoginForm`), далі дотик у поле, перемикання (на iPhone для картки стрілкою «Наступне» над клавіатурою, її координати від верху нативної клавіатури; для входу й на iPad дотиком у друге поле), закриття дотиком по підкладці (перший дотик ховає клавіатуру, другий закриває лист).
- Події з рекордера застосунку: `kb-geometry`, `sheet-open`, `sheet-anim`, `tabbar-restore` тощо (`debugEventBuffer`).

## Еталон замість порогів телефону
- Кадри, паузи й тривалість `sheet-anim` на симуляторі інші, ніж на телефоні, тож абсолютні пороги (≥ 12 кадрів, пауза ≤ 34 мс) давали хибні падіння. Тепер `docs/ui/sim/baseline.json` зберігає медіану прогрітих проходів симулятора для версії, і прогін ловить **погіршення**: кадрів менше ніж 75% еталона; пауза більша ніж ×1,5 (мінімум +12 мс); тривалість більша ніж ×1,5 (+60 мс); положення листа/поля відрізняється від еталона більш ніж на 2 пт.
- Оновлювати еталон (`SIM_UPDATE_BASELINE=1`) лише після перевірки, що поточний стан правильний; у `summary.md` видно версію еталона й попередження, якщо вона відстає.
- Абсолютними лишаються інваріанти, що не залежать від швидкості: клавіатура з'явилась/зникла, фокус у потрібному полі, `kb-open`, таб-бар ≥ 21 пт від низу. Позиція: для листа з новим конвеєром (вхід, iPhone) низ листа на 8 ± 2 пт над краєм видимої області; для картки на iPhone (старий конвеєр, E2E 38) поле має бути над клавіатурою. На iPad інваріанти iPhone не застосовуються (лише функціональні й відносні).
- Окремий рядок «перше відкриття після запуску застосунку (холодна клавіатура)» не порівнюється з еталоном, лише з функціональними вимогами. Решта сценаріїв береться з прогрітих проходів.

## Результати
`docs/ui/sim/<версія>/`: `summary.md` (сценарій → пройшов/впав → причина), JSON на сценарій (метрики, події, значення по проходах), знімки до/після у JPEG (390 пт, якість 45; якщо > 300 КБ на сценарій, лишається лише JSON). `appium.log` лежить там же (не комітиться).

## Розбір 19 падінь SIM-1 (вкладка Safari, абсолютні пороги)
| Падіння | Висновок |
|---|---|
| «Картка боргу не піднімається над клавіатурою» (iPhone портрет) | **Справжнє, але лише для першого відкриття після запуску**: у PWA на другому й далі відкриттях низ листа на 8 пт над краєм видимої області, а на першому (холодна клавіатура) поле «Борг по карті» під клавіатурою (≈ −149 пт). Тепер окремий рядок «холодна клавіатура». У вкладці Safari додавалося спотворення (`visualViewport` враховує панель Safari). **Перевірити на телефоні**: перше відкриття картки після холодного запуску. |
| Пауза/кадри/тривалість `sheet-anim` понад пороги | Пов'язане з вимірюванням (симулятор повільніший); замінено еталоном. |
| «Стрибок» при відкритті/закритті | Помилка критерію (лист їде на всю висоту); перевіряється лише при перемиканні полів. |
| iPad: низ листа −182…−322 пт, немає `kb-open` і `sheet-anim` | Помилка критерію: інваріанти iPhone не для iPad; зараз лише функціональні й відносні. |
| iPad: у вході фокус лишається в email після дотику в пароль | **Нерозібране, імовірно вимірювання** (поле зміщується після першого фокуса між зчитуванням координат і дотиком); лишається падінням у двох конфігураціях. |
| iPhone ландшафт: картка, поле під клавіатурою (−230 пт) | Імовірно справжнє (видима область з клавіатурою ≈ 139 пт); **перевірити на телефоні**. |
| iPhone ландшафт: вхід, дотик у email потрапляє в поле (за координатами), але клавіатури нема, фокус у `profile-drawer` | **Нерозібране**: може бути справжнім (фокус не ставиться) або особливістю дотику; **перевірити на телефоні**. |

## Обмеження
- Симулятор повільніший за телефон; цифри еталона з нього не переносяться на телефон.
- Стрілка «Наступне» над клавіатурою знаходиться за координатами від верху нативної клавіатури (її нема в нативному дереві SpringBoard); для інших мов/розкладок клавіатури може знадобитися корекція.
