# NOTIF-3: push Monobank іноді не показується на iPhone (клас C)

Перенесено з Notion один раз (21.10); Notion більше не відкривати. Публічний репозиторій: без реальних даних.

## Симптом (16.10)
Три операції Monobank підряд: пуші для двох перших прийшли одразу, для третьої (08:52 UTC) на телефон не прийшов. Далі не приходило нічого: 11:52 і 20:00 за Києвом теж. Сервер для всіх відправив: `push_delivery_log` `sent: 1, failed: 0, status 201`, `urgency high`, `ttl_s 43200`. Журнал «Отримано на цьому пристрої» не має записів за 11:52 і 20:00 (усе інше збігається із серверним списком). Андрій: застосунок був закритий або у фоні, «Не турбувати» і Фокусу не було. Гіпотеза Андрія «3-тє приходить разом з наступним» не підтверджена. Нагадування о 17:00 UTC для Андрія мало `type='mono-inbox'`, `tag='daily-expense-reminder'` (один рядок на члена сім'ї).

## Висновки Кроку 0 (прийнято чатом)
- Обробник `push` у `sw.js` не мав умов «не показувати», але `showNotification` ішов після запису журналу в IndexedDB без тайм-ауту (гіпотеза H1, найімовірніша). Альтернатива: «спляча» підписка (APNs приймає, воркер не запускається).
- `getNotifications()/close()` у застосунку немає; підміна за `tag` не пояснює спостереження. `pushsubscriptionchange` і `notificationclose` не оброблялись; дії «Оновити підписку» й ознаки «сплячої» підписки немає.
- `send-test-push` нерепрезентативний (без `urgency`/TTL, не пише в журнал сервера). Серія тестів з клієнта у фоні неможлива (таймери PWA зупиняються).

## Рішення чату
1. Три окремі Rev: Rev 1 (`sw.js`), Rev 2 (режим розробника), Rev 3 (серія тестових push).
2. Базовий журнал «Отримано на цьому пристрої» (30 записів) лишається завжди ввімкненим: запис ПІСЛЯ `showNotification`, тайм-аут ≈ 1 с, без `title`.
3. Розширене: лише за перемикачем розробника, вимкнено за замовчуванням, прапорець в IndexedDB. `push_ack` відкладено.
4. Сервер готовий (чат): `data.push_id` (uuid) у кожному push, таблиця `push_sent_log` (14 днів), RPC `start_test_push_series(p_count int default 6, p_intervals_s int[] default '{60,60,300,600,600}', p_tag text default 'mono-inbox') returns uuid` (authenticated; 1..10 push; перший через 60 с; інтервали ≥ 60 с; одна активна серія на користувача, інакше помилка `series already running`), `run_test_push_series`, cron `test-push-series` (існує лише під час серії). Тестові push не пишуться в `user_notifications`.

## Rev 1 (виконано, 2.32.101)
`showNotification` першим без `await`; журнал після показу з тайм-аутом, без `title`; `try/catch` довкола обробника з мінімальним показом; нова версія.

## Rev 2 (режим розробника; чекає слова чату)
Перемикач «Розширена діагностика сповіщень» («Сервіс» → «Тестування»), вимкнено за замовчуванням; прапорець в IndexedDB (`budget-app-push-diag`), який читає воркер (після показу). Увімкнено: кільцевий журнал ≈ 200 подій (`push-received` з `type`, `tag`, `batch_ts`/`seq`/`series_id`/`push_id`, `show-ok` з тривалістю, `show-skip` з причиною, `show-error`, `handler-error`, `closed`, `click`, `subscription-change`, `activate`; без тексту сповіщення, сум, назв). Показ у панелі діагностики; у «Надіслати лог сповіщень» (окрема кнопка, лише за натисканням) потрапляє журнал і знімок стану. Знімок: `standalone`, iOS за UA, `Notification.permission`, наявність підписки і хеш endpoint (перші 8 hex SHA-256), версія воркера і `waiting`, `online`; недоступне на iOS (режим низького заряду, `connection.effectiveType`) позначати `unavailable`. «Оновити підписку» (`unsubscribe` + `subscribe` + `claim_push_subscription`, хеш до/після) лише в цьому режимі. Вимкнено: жодних додаткових записів і запитів.

## Rev 3 (серія тестових push; лише режим розробника; чекає слова чату)
Форма (кількість 1–10, інтервали в хвилинах ≥ 1, `tag` за замовчуванням `mono-inbox`), кнопка «Запустити серію» (RPC), стан «серію запущено, закрийте застосунок і заблокуйте телефон», помилка `series already running`. Без клієнтських таймерів. Воркер для `type='test'` будує сповіщення з тими ж `tag`/`renotify`, що й `mono-inbox`, коли `tag` переданий.

## Матриця
IndexedDB не відповідає; виняток у тілі; режим вимкнено (нічого зайвого); увімкнено (збереження між перезапусками, буфер ≤ 200); «Надіслати лог сповіщень» (без текстів, обмежений розмір); недоступні API; «Оновити підписку»; серія; закритий/згорнутий/відкритий застосунок, «Не турбувати»; основний режим без додаткових запитів.

## Алгоритм збору даних для Андрія (після Rev 2–3)
Перевірити Налаштування iOS → Сповіщення → Money Tree (дозволи, «Миттєва доставка»), «Економію заряду»; увімкнути «Розширену діагностику сповіщень»; запустити «Серію тестових push»; при реальному пропуску записати час, не відкривати застосунок, подивитись Центр сповіщень, потім скріншоти панелі й «Надіслати лог сповіщень».
