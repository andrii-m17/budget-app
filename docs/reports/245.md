# Rev 245 (застосунок 2.32.244, ID-ALL): картки, категорії, підкатегорії й слова впізнаються лише за id (клас C, не запушено)

## Що зроблено
- Spec-и `bankIdSpec`, `categoryIdSpec`, `subcategoryIdSpec`, `dictionaryIdSpec` у спільному механізмі; нова `idPushPlain` (update за id → за 0 рядків GET за id → insert з тим самим id або прийняття надгробка).
- Прибрано пошук за назвою/ключовим словом: чотири `reconcile*CloudId` і гілки `byName`/`byKw` у чотирьох pull. Додано підтвердження `clientId → cloudId` у pull.
- Правило міграції для всіх, включно з ОЧ: мітка до мс (живі й надгробки) → один кандидат: зв'язати; кілька: додаткова ознака (ОЧ сума, картка/категорія/підкатегорія назва, слово ключове слово без регістру); не обрано: нічого + подія без назв; жодного: новий id. Сума ОЧ більше не частина ключа (раніше змінена сума давала дубль).
- Неоднозначні записи не зв'язуються в сеансі «методом викреслювання» (`ID_AMBIGUOUS`).
- Слова: 23505 через `dictionary_live_keyword_uniq` → `keyConflict` → усиновлення (варіант А); через `_pkey` → GET за id. Перевірка збігу слова до збереження в формі вже є, нового тексту не додавав.
- Нові записи дістають `clientId`; перейменування ставить `nameDirty` (назва шлеться без зліпка лише тоді). `keepId` у переписі id для карток, категорій, підкатегорій, слів.
- ROADMAP 32.303 (з пунктом «Посилання підкатегорій, слів і витрат на батька за id»), STATUS, два кроки «Перевірок» 2.32.244-1/2.

## Відхилення від погодженого
1. Типові категорії: `ensureCategoryIdentity` уже проставляє їм `createdAt` = час пристрою (не збігається між пристроями), тож правило «лише без мітки» їх не ловило, а e2e показав дублі. Їм додано `seed: true`: для seed і записів без мітки — точна назва, рівно один кандидат на обох боках; мітка береться серверна, позначка знімається.
2. Додаткова ознака підкатегорії — лише назва (без батька: його id може бути ще невідомий).

## Відкриті ризики (рішення за чатом)
1. Відновлення зі старої копії з «мертвим» cloudId, коли на сервері є рядок з тією назвою під іншим id: pull більше не зв'язує за назвою, можливий дубль (картка, категорія, підкатегорія). Це 246; тесту на це нема.
2. Телефон зі старим застосунком і НЕсинхронізованими типовими записами без `seed`: мітка пристрою не збігається, будуть дублі. Для вже зв'язаних записів проблеми нема.
3. Одночасний перший запуск двох чистих телефонів: можливий дубль типових категорій (раніше теж, select-потім-insert; унікальності назв на сервері нема).
4. Неоднозначний запис лишається локальним, pull додає серверні рядки окремо: для карток і категорій дубль видно користувачу до ручного втручання.
