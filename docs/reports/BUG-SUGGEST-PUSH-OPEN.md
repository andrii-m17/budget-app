# BUG-SUGGEST, BUG-PUSH-OPEN, PUSH-MAP (19.11.2026)

## BUG-SUGGEST (Rev 2.32.403, клас C → лише запис)
- Не відтворено. Симулятор iPhone 16 Pro Max, реальні дотики (Appium, PWA з головного екрана, мок, екранна клавіатура, набір клавішами): підказка вибирається з першого дотику на 2.32.371, 2.32.389 і 2.32.402 (по 3–4 спроби, затримка після набору 50–700 мс, тривалість дотику 0–250 мс, після свайпів, фікстури typical і large). Під пальцем завжди рядок підказки; список не рухається (зсув < 1 пт); `Touch.identifier` зростає (застарілих ідентифікаторів нема).
- Між 2.32.371 і 2.32.402 код і CSS підказок не змінювались (немає жодного рядка з `suggest`/`nsi-`), змінились лише оточення: відступи форми (DS-4d2), слухачі `document` у DS-3c4 (пасивні, capture, нічого не гасять).
- Зроблено: подія самописця `suggest-tap` у бортовому буфері (потрапляє у «Повідомити про проблему»): `ts`/`te`/`tc`/`click` у прямокутнику видимого списку (`inList` — чи влучив сам список, інакше `targetTag`/`targetClasses` того, що перехопило), `fieldFocus`, `lagMs`; `pick` (вибір відбувся) і `skip` з `reason` (`pick-400ms`, `late`, `handled`, `rejected`, `moved`, `timer-state`, `list-changed`). Без тексту назв.
- Сценарій симулятора: `node e2e/ios/suggest.mjs --trials N` (`SIM_KEYS=1` — набір клавішами, `SIM_DELAY`, `SIM_HOLD`, `SIM_SWIPE`, `SIM_FIXTURE`).
- Далі: якщо вада повториться, у звіті (`client_debug_logs`, `scenario='incident'`) шукати `suggest-tap`: `inList=false` → щось перекриває список; `skip` з `reason` → які гілки відкидають дотик; жодної події → дотик не доходить до сторінки.

## BUG-PUSH-OPEN (Rev 2.32.404, клас C)
- Знайдено два шари. (1) Код: запис дії з IndexedDB на `pageshow` ставив мітку кліку `_at` у `handledPushStamps`, але виконати дію не міг (сторінка ще `hidden`); `message` від SW з тією ж міткою відсікався як `duplicate` без спроби виконати очікувану дію, а `visibilitychange` уже минув. Це точно відповідає записам самописця (`push-msg source=idb-pageshow` → `push-apply reason=duplicate skipped`). Виправлено: дублем вважається лише клік, чия дія вже виконана або чекає запуску; не виконану дію той самий клік у видимій сторінці запускає (`push-apply result=retry`); якщо сторінку сховали до виконання, одна відкладена спроба через 700 мс. Отримання сповіщення мітки не ставить ніколи (вона є лише в `notificationclick`).
- (2) Платформа: WebKit 268797 — при відкритому застосунку `notificationclick` взагалі не викликається; для `other-actor-summary` у застосунку немає ні декларативного формату, ні тоста (є лише для `mono-inbox`). Цю частину клієнтський код не лікує: потрібне рішення (серверний декларативний формат для зведень або тост «Переглянути» в застосунку).
- Тести: `tests/push-open.test.js` (8: відкрите, hidden→visible, фон, закрите, сон, окремі дотики, діагностика; сценарій hidden→message падав на 2.32.403), `e2e/push-tap.spec.js` PUSH-OPEN 1–3.
