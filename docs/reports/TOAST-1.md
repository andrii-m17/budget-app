# TOAST-1: нове повідомлення замінює поточне (Rev 2.32.297, клас B)

Стан: реалізовано, не запушено (чекає слова чату).

## Крок 0 (відповіді)
- **Черги.** Було: `successToastQueue` + `pumpSuccessToast` (по одному). Тепер черги немає, змінну видалено.
- **Усі шляхи показу йдуть через `showToast`:** `showTextToast`, `showMonoAddedToast`, картка конфлікту (`conflictFlushCards`, 8047/8051), «Позначено сплаченим» (11184), підсумок push (12148), `toastModel`-виклики (13118, 13167), «Спершу почніть запис діагностики» (23134), повернення Monobank (25176). Окремих контейнерів плашок немає (`update-banner`, `mono-banner`, банер помилки збереження це банери, не плашки; не чіпались).
- **Конфлікт після заміни не втрачається.** Запис потрапляє в `conflictLog` (7949, зберігається) до показу картки; `conflictOpenCount()` рахує необроблені (лічильник дзвіночка, 25281); журнал сповіщень показує їх із діями.
- **`toastFitText`.** Сумісний без поступок: після підстановки вмісту викликається `toastFitText`, потім міряється новий розмір, а рух розміру йде на Web Animations (`width`/`height`) поверх уже готового розкладу, тож миттєвого розміру не знадобилось (п. 9 ТЗ не спрацював).

## Що зроблено
- `showToast`: є активна плашка → `replaceSuccessToast` (елемент той самий), інакше `pumpSuccessToast` (перша поява `stIn`, без змін).
- Рух: старий вміст 120 мс (прозорість 1 → 0, зсув 6 px угору) → підстановка → ширина й висота за 200 мс `cubic-bezier(.2,.8,.2,1)` + новий вміст 160 мс (зсув 6 px униз, прозорість 0 → 1); іконка домальовується наявною `stDraw`.
- Той самий вміст (`toastSignature`: kind, іконка, заголовок, підзаголовок, кнопки, sticky/compact): лише скидання таймера і пульсація `scale` 1 → 1,03 → 1 за 180 мс `ease-out`; зворотні виклики кнопок беруться з найновішого повідомлення.
- Заміна під час виходу: вихід скасовується (`toastCancelLeave`, `stIn` не перезапускається); один елемент у контейнері. Палець на плашці: вміст міняється, зсув скидається, таймер нового стартує після відпускання. `sticky` береться з нового повідомлення (в обидва боки). Один `successToastTimer`.
- Зменшений рух: лише перетікання прозорості (по половині `--motion-s` на згасання й появу), без зсуву, руху розміру й пульсації.
- Лише `opacity`, `transform`, розмір; нових бібліотек немає; CSS не змінювався (рух на `Element.animate`).

## Відхилення і ризики
- Рух на Web Animations API: у дуже старому WebKit без `Element.animate` вміст міняється миттєво (без руху), функціонально все працює.
- У зменшеному русі «перетікання за `var(--motion-s)`» реалізовано як дві фази по половині `--motion-s` (разом одна `--motion-s`).
- Версію піднято 2.32.296 → 2.32.297 (`APP_VERSION`, футер, `CACHE_NAME`).

## Для iPhone (крок для «Перевірок»)
Стан: застосунок відкрито, будь-який екран. Дія: швидко тричі торкнутись кнопок, що дають різні повідомлення (наприклад «Сервіс → Monobank»: відкрити й закрити «Вхідні», натиснути «Оновити токен» з порожнім полем), потім повторити одну й ту саму дію кілька разів. Видимий результат: на екрані одна плашка, яка плавно змінює текст і розмір без стрибків і обрізання, одна й та сама дія лише слабко «пульсує» без блимання, плашка зникає через один інтервал після останньої дії; картка конфлікту, замінена іншим повідомленням, лишається в журналі сповіщень із лічильником на дзвіночку.

## Рев'ю (`spec-reviewer`)
Блокерів немає. Усунуто: закриття під час згасання (старий вміст не «вертається»), `touchcancel` (пауза таймера не залипає), позиція хоста при повторі того самого вмісту; додано тест. Лишається на пристрої: затримка домальовування іконки `success` після заміни (≈ 0,6 с, наявні затримки `stDraw`) і озвучення VoiceOver при зміні вмісту в `role=status/alert` (на місці роль міняється через `setAttribute`).
