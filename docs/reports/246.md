# Rev 246 (застосунок 2.32.246, RESTORE-ID): відновлення з копії й Excel-імпорт без дублів, видалення назавжди (клас C, не запушено)

## Що зроблено
- **Відновлення** (`mergeBackupRecordsByCloudIdOrName`): запис копії впізнається за id; без id або з чужим — за міткою створення до мс серед ще не зіставлених локальних (кілька — за назвою; не вибрано — пропуск); підкатегорії порівнюються разом з категорією; пошук за назвою лише для записів без мітки й `seed`. Знайдений: правка полів, **назва береться з копії** (`nameDirty`). Не знайдений: якщо живий запис з такою назвою вже є — пропущено (тост: «Повернуто N записів. Пропущено M: вони вже є в застосунку під такою самою назвою.»); інакше повертається під своїм id (`clientId` + `restoreReturn`): надгробок з тим id оживає, відсутній рядок створюється з ним. Тест 243-4 зелений.
- **Excel**: нові картки й ОЧ (за назвою) питає наявна модалка з вашим текстом («Додати як нові» / «Пропустити», понад п'ять назв «та ще N»). Відмова прибирає нові картки/ОЧ і їхні борги цього імпорту. Витрати, доходи й борги вже були ідемпотентні: той самий файл двічі додає 0 (сценарій 13).
- **Видалення назавжди (нова помилка).** Картки, ОЧ і категорії за задумом PURGE-1/T2 **не видаляються фізично, а отримують надгробок** (`deleted_at`; FK боргів), сервер стирає їх за 14 днів; `purgeCloudRow` (фізичний `DELETE`) лише для витрат, доходів, місячних боргів і слів. Тому «рядок досі на сервері» для трьох ОЧ може бути надгробком; перевірте їхній `deleted_at`. Реальні ризики на цьому шляху виправлено: видалення йшло за назвою (при однакових назвах знищувався перший за списком), запис лише з `clientId` не видалявся на сервері, 0 оновлених рядків вважалося успіхом. Найімовірніша причина вашого випадку — дублі за назвою або `clientId`, але це гіпотеза: робочу базу я не читав.
- **Знайдено по дорозі**: два одночасні виклики `idMigrateUnlinked` для однієї таблиці (збереження + push імпорту) давали різним копіям запису різні id → два рядки (сценарій 13 це відтворив). Виклики тепер по черзі. Також слово без правки тексту після push не мало зліпка: тепер текст береться з відповіді сервера.
