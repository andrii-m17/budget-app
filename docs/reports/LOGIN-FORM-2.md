# LOGIN-FORM-2: автовхід після Face ID і стрибки форми входу (Rev 2.32.327, клас C)

Стан: реалізовано, не запушено (чекає слова чату).

## Крок 0
1. **Події WebKit при автозаповненні.** Вихідний код WebKit (`TextFieldInputType::setValue`, `HTMLInputElement::setValueForUser`, автозаповнення облікових даних) у цьому середовищі не читався, тож твердження про те, які саме події (`input` з `inputType`, `change`, лише `change` для поля без фокуса) і чи виставляється `:-webkit-autofill`, **не підтверджено за кодом**. Доказ лише з самописця (MT-1117-1653, -3640): `autofill` з `by: panel` / `closed` (тобто ознак `input` без `inputType` / `insertReplacementText` не було), а `login-submit by: autofill` відсутній: умови 2.32.326 (ознака autofill у `input`, «без дотику по полях») не збігалися з тим, що подає iOS. Тому умови автовходу зроблено незалежними від ознаки autofill і подій (`input` і `change`), а самописець отримав `login-fill` з `autofill` (збіг `:-webkit-autofill`), щоб на пристрої це побачити.
2. **Чому перехоплення дотику пропускало поля входу.** Не через обгортку `<form>`: перехоплення спрацьовує для елемента `form` (елемент підходить під `resolveTapFieldNear`; тест 132 перевіряє дотик по проміжку саме з `target` = `form`). Причина — виняток «полів платформи» з Rev 2.32.322 (FACEID-RESTORE): прямий дотик по `input` поля входу при закритій клавіатурі свідомо не перехоплювався ні на `touchstart`, ні на `touchend`, тому фокус ставив iOS (`intercept-miss`, `pan-corrected` 361). Дотики по обгортці `.field`, іконці й заголовку йшли через перехоплення (`focus-proxy`), звідси +14,6/+17,5/+22,0 с у 3640 проти +19,4/+20,7 с. Порівняння з 2.32.323: те саме (виняток був і там). Дотик у проміжок `cloud-login-fields`, якщо він не перехоплений, на мок-прогонах перехоплюється; причину на пристрої не відтворено.

## Зроблено
- **Автовхід.** `input` і `change` на обох полях → через 300 мс `loginAutoCheck`: обидва поля не порожні; у полях входу не було `keydown` після відкриття форми / очищення полів; вхід не триває; цю пару значень ще не подавали → один `form.requestSubmit()` (`login-submit by: autofill`). Друге джерело: завершення групи `autofill` у самописці (будь-який `by`) викликає ту саму функцію. Умову «не було дотику» прибрано.
- **Самописець.** `login-fill` на кожну `input` / `change` у полях входу: `field`, `ev`, `inputType`, `autofill`, `filled` (значень не пишемо).
- **Стрибки.** Виняток «полів платформи» для прямого дотику при закритій клавіатурі прибрано (`touchstart` і `touchend`): поля входу знову йдуть шляхом першого дотику (перехоплення / `focus-proxy`). `kbIsPlatformField` лишився для KB-SHOT, перекидання фокуса (`autofill by panel`, без `kbNavLock`) і `platformField` у `sheet-open`.

## Відхилення
- Ключ `hasValue` з ТЗ перейменовано в `filled`: тест приватності самописця забороняє підрядок `value` у назвах ключів.
- Крок 0 п. 1 не підтверджено за кодом WebKit (див. вище).
- Дотик у проміжок на пристрої без перехоплення не відтворено на моку: покрито тестом, причину лишено для звіту з пристрою (`login-fill`, `intercept-miss`).
