# DS-PAYLIST · Крок 0: екран «Платежі», структура й внесення через витрату (клас C)

Лише читання коду (`js/payments.js`, `index.html`, `css/app.css`, `docs/FINANCIAL_RULES_AND_OBLIGATIONS.md`, `docs/UI_PATTERNS.md`) і макета v4 (`Main`, `Sheet`; `Light` тієї ж структури, окремо не відкривав). Нічого не змінено, у базу не заходив. Лише синтетичні приклади.

## 1. Що відкриває дотик зараз і чи вміє форма прийняти прив'язку

- Рядок екрана (`renderPaymentsScreen`, `js/payments.js:529`) → `openPayAction(item)` → шторка `#pay-action-drawer` з двома кнопками. Для ОЧ: «Внести платіж» (`payInstallmentPrefill`) і «Відкрити в «Обліку»». Для картки: «Позначити сплаченим» (`markCardMinPaid`: лише `minPaymentDone`, витрата не створюється).
- `payInstallmentPrefill` (`js/payments.js:601`) закриває екран, перемикає на вкладку витрат і підставляє:
  - назву `#expfielda7` (ім'я ОЧ без емодзі);
  - суму `#f-amount` (`item.amount`, очікувана теж; через `formatThousands`, **без округлення**);
  - дату `#f-date` = **дата платежу** (не сьогодні), `rolloverState.dateManual = true`;
  - категорію: активна «🏦 Оплати Частинами» за точною назвою (`setCategorySelect`);
  - прив'язку: `confirmedInstallmentLinkIdx = індекс ОЧ` і підказка «🔗 Прив'язано до «X»» (`renderInstallmentLinkHint`, `index.html:10724`).
- **Номера платежу в моделі прив'язки немає.** Витрата зберігає лише `linkedInstallment` (назва) і `linked_installment_id` (`index.html:4314, 5171`). До якого платежу вона належить, визначає **місяць дати витрати** (`upcomingPayments`: `String(e.date).slice(0,7)`). Тому «Платіж k+1 з n · за <дата>» можливий лише як відображення, а не збережене поле.
- Нових полів вводу в плані немає: форма наявна, блок «Прив'язано…» розширює існуючу підказку `#installment-link-hint` (не поле).

## 2. «Потребує уваги» зараз

`upcomingPayments` (`js/payments.js:213`), функція `place()`:
- ОЧ: `past = installmentDuePassed(month, dueDate, today)`: місяць до поточного → так; поточний → `today > dueDate + 1 день` (пільговий день, Rev 2.32.152). Картка: `date < today`.
- У `unconfirmed` потрапляє лише `past && item.month === m0` (поточний місяць). Платіж ОЧ із датою вчора (пільговий день) **не** в `unconfirmed`, а в `items` з `overdue: true` (Rev 2.32.396).
- Місяці рахуються лише `[m0, m1]` (поточний і наступний). Невнесений платіж **минулого** місяця на екран не потрапляє ніколи.
- Дата «сьогодні»: `kyivTodayISO()` (Europe/Kyiv), арифметика дат через UTC-ISO (`ppAddDays`, `ppDayDiff`), без зсуву поясів. Але дата за замовчуванням у формі витрат: `localDateISO()` (пояс пристрою), тож за кордоном «сьогодні» у формі може відрізнятись від Києва.

## 3. Звідки беруться дані рядка

| Дані | Джерело | Зауваження |
|---|---|---|
| «k з n» | **на екрані зараз немає** | n = `acc.termMonths` (може бути `null`). k: або `ochPlannedPaymentsBefore(startDate, firstPayment, term, month) + 1` (потрібні `startDate`+`termMonths`), або з ланцюжка: `k-1 + installmentPaymentsLeft(before, payment)`. Два джерела можуть розходитись. Без терміну показати «ОЧ» без «k з n» |
| Логотип | `bankIcon(name, size, block, kind)` (`js/analytics.js:15`): лише відомі банки, інакше нейтральне коло (Rev 2.32.157) | зараз рядок показує плитку дати, не логотип |
| Тип платежу | `item.kind`: `installment`, `card` | **інших типів на екрані немає** (обов'язкових платежів у `upcomingPayments` немає) |
| Очікувана сума | запис місяця `monthlyPayment` → стандартний платіж моделі ОЧ (`installmentPayAmount`) → мода попередніх (`installmentTypicalPay`, `estimated:true`) | суму моделі може бути дробовою; `amount:null` = «сума невідома» |
| Картка | `rec.minPayment > 0` і не `minPaymentDone`; без дня платежу → `undatedList` | дія «Позначити сплаченим» без витрати |

## 4. Ризики подвійного внесення

1. **Внесено вручну без прив'язки:** платіж вважається сплаченим лише за `linkedInstallment` (сума прив'язаних витрат ≥ очікуваного). Непривʼязана витрата не рахується, картка «Чекає внесення» лишається, користувач натискає «Внести платіж» і створює **друге витрату**. Захист: у підстановці знайти нерозпізнану витрату з тією ж назвою/сумою (±1 %) у місяці платежу і показати підказку «Схоже, вже є витрата… прив'язати її замість нової?». Підказка, не нове поле.
2. **Автоприв'язка (`docs/FINANCIAL_RULES_AND_OBLIGATIONS.md` §5, C):** підказка за назвою, лише після явного підтвердження. Наша підстановка ставить прив'язку попередньо підтвердженою, що узгоджується з варіантом B («Оплатити ОЧ»); дозволено документом. Ризик: `updateInstallmentLinkDetection` скидає прив'язку, якщо після зміни назви збіг зник; у запасу — перевірка `isInstallmentVisibleForMonth` за місяцем дати.
3. **Два пристрої:** пристрій A і B одночасно (до синхронізації) створюють по витраті: LWW за id не зливає різні записи, виходить дві прив'язані витрати → стан «внесено більше». Блокування на офлайні неможливе. Реально лише після синхронізації картка зникає на другому (realtime → `renderAll`), **але відкритий екран «Платежі» сам не перемальовується** (`renderPaymentsScreen` викликається лише з `openPaymentsScreen`, `js/payments.js:561`): потрібен перерендер за подією синхронізації. Ризик лишається для вікна офлайну.
4. **Дата і місяць:** `payInstallmentPrefill` ставить дату платежу. Макет і ТЗ кажуть «сьогодні». Для платежу **наступного місяця** (розгорнутий «Пізніше») «сьогодні» прив'язало б платіж до **поточного** місяця: він отримав би «внесено більше», а наступний лишився б невнесеним. Для платежів поточного місяця (і «Чекає внесення») «сьогодні» безпечне.
5. **Чернетка форми витрат:** `payInstallmentPrefill` перезаписує поля, не питаючи; наявна незбережена чернетка (інша витрата) втрачається.
6. Округлення: `item.amount` може бути дробовим (`initial/term`); правило «лише цілі гривні» вимагає `Math.round` при підстановці й у плитках (нині `payFmt` лише форматує).

## 5. Розбіжності ТЗ / макет / код (потрібне рішення чату)

1. **«Чекає внесення» = дата до сьогодні, а код: пільговий день.** ОЧ із датою вчора зараз у «Найближчих» з `overdue`, а не в «Потребує уваги». Узгодити: чи зникає пільговий день на цьому екрані (вчорашній платіж → «Чекає внесення»)? Формули `installmentDuePassed`/`installmentPaymentState` (використовує «Облік» і рядок ОЧ) не чіпаю без прямого слова.
2. **Невнесений платіж минулого місяця** не показується (лише `m0`,`m1`). Показувати? Це зміна `upcomingPayments`, тобто клас C, і вимагає окремого рішення.
3. **Слово «Прострочено»** живе також у картці «Найближчі платежі» (`js/payments.js:321, 362`) і у підписі рядка (`:512`). ТЗ забороняє слово на екрані; у картці лишається? (Rev 2.32.396 додав його свідомо.)
4. **Картки (мінімальний платіж):** ТЗ каже «платіж ОЧ фіксується лише через витрату» і не згадує карток. Наразі в картки дія без витрати (за правилом «зміна балансу картки ніколи не витрата»). Лишаємо «Позначити сплаченим» для карток у «Чекає внесення»? Кнопка «Внести платіж» для картки створила б витрату, що суперечить цьому правилу.
5. **Дата «сьогодні» vs дата платежу** (ризик 4): пропоную «сьогодні», якщо платіж у поточному місяці, інакше дата платежу.
6. **Макет vs наявна форма:** `Sheet` показує окрему шторку «Внести платіж ОЧ» з полем «Рахунок списання» і категорією «ОЧ · Техніка». У застосунку такої шторки й поля немає: це вкладка «Витрати» (назва, сума, дата, категорія, підказка прив'язки). За ТЗ («наявна форма») реалізую блок «Прив'язано до ОЧ · назва · Платіж k+1 з n · за дата» в наявній формі, без «Рахунку списання». Підтвердити.
7. **Макет:** синій підпис плитки «Цей тиждень» (ТЗ: «синіх крапок не робимо», про підпис плитки мовчить), кнопка pill 999 px, радіуси 14/18 і розміри шрифтів задані жорстко; перевірю за `docs/UI_PATTERNS.md` (основна кнопка форм: 18 px `--ui-r-control`, `submit-btn pill` є) і токенами. «Пізніше» у макеті: «7 платежів · 5 ОЧ» (ТЗ просить «≈ суму»). Підпис «сума очікувана» в рядку макета не в ТЗ.
8. **Три місяці в тесті:** реальні дані мають лише два місяці (`m0`,`m1`). Групувальну функцію роблю загальною, тест на 3 місяці перевіряє її на синтетиці.
9. **Типи платежів:** на екрані лише ОЧ і картки; «обов'язкові» з вашого ТЗ-прикладу тут не з'являються.

## Матриця сценаріїв (скорочено)

| Вісь | Що перевіряю |
|---|---|
| Дані | порожньо; 1 платіж; ≥ 30 на 3 місяці; ОЧ без суми / без графіка / без терміну; n = k |
| Дати | пн/нд, 1, 15, 31, вікно 14 днів через межу місяця, груд → січ; плитки не перетинаються, сума плиток = сума списку |
| Прив'язка | сума ціла; очікувана не записується без «Зберегти»; дата сьогодні / дата платежу; чернетка не губиться |
| Подвійне | уже внесено вручну без прив'язки; два пристрої (`e2e:cloud`); офлайн-внесення |
| Вигляд | темна/світла, 390 пт, 320, iPad, десктоп; ціль ≥ 44 px |

## Питання до чату

1. Пільговий день ОЧ: вчорашній платіж ідеться у «Чекає внесення» на цьому екрані (без зміни формул «Обліку»)?
2. Показувати невнесені платежі минулого місяця (зміна `upcomingPayments`)?
3. Картки: лишаємо «Позначити сплаченим» без витрати (так — без «Внести платіж»)?
4. «Прострочено»: прибрати лише з екрана чи й з картки «Найближчі платежі»?
5. Дата форми: «сьогодні» для поточного місяця, дата платежу для наступного. Згода?
6. Форма: блок «Прив'язано до ОЧ…» у наявній формі «Витрати», без «Рахунку списання» з макета. Згода?
7. Дубль: показувати підказку «схожа витрата вже є» (Rev 2)?
8. Без терміну/графіка ОЧ показувати «ОЧ» без «k з n»?
