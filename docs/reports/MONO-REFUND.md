# MONO-REFUND: автоматичне зіставлення повернень Monobank (Rev 2.32.330, клас C)

Стан: реалізовано, не запушено (чекає «можна пушити»). Макет: `docs/ui/mockups/mono-refund-mockup.html`; виміри в `docs/UI_PATTERNS.md`.

## Що зроблено
- **Рядок списання з поверненням (Нові):** сума = `net_uah ?? amount_uah`, нижче закреслена стара, мітка «↩ Повернено N ₴ із M ₴» (форма `.mono-inst-label`, `--color-info-bg`/`--color-info`). «Додати», «Додати всі», тост «Додано» беруть чисту суму; списання з нульовою чистою сумою не додається.
- **Рядок-підказка:** `skipped` + `refund_suggest` показується у «Нових», входить у лічильник (сервер), сума «+», мітка-кнопка «↩ Повернення до витрати <дата>, <сума> ›» (дані списання другою вибіркою). Тап по мітці: шторка рядка + діалог вибору (запропоноване перше). Свайп: «Ігнорувати» і «Врахувати» (застосовує запропоноване з підтвердженням).
- **Пропущені:** «Повернення враховано автоматично» / «Повернення враховано»; `refunded_full` → «Повернено повністю»; у шторці «Скасувати зіставлення» (підтвердження, `mono_refund_undo`) для `refunded` з `refund_of`. Рядки-підказки з «Пропущених» виключено.
- **Діалог вибору:** `mono_refund_options` (замість `mono_refund_candidates`); `new` → `mono_apply_refund_inbox(p_inbox_id, p_charge_inbox_id)`, `added` → `mono_apply_refund(p_inbox_id, p_expense_id)`.
- **Тост:** `sync_heads().mono_refund_at` змінився → вибірка `refund_auto = true`, `decided_at > попередня мітка` + друга за `refund_of`; тост `info` «Повернення N ₴ враховано» / «<назва>: M ₴ → K ₴» (або «→ видалено») лише при `expense_id`; один раз на id (`localStorage`, до 100 id, без сум); перший раз лише запам'ятовує мітку; до 3 тостів послідовно. Без кнопки й push.

## Відхилення і ризики
- Тост приходить із наступною перевіркою голів (старт/повернення з фону/Realtime інших таблиць), не миттєво: Realtime на `mono_inbox` немає (рішення чату).
- Мітка-підказка на 390 пт переноситься на два рядки (сума не відривається від «₴» нерозривним пробілом) замість обрізання: у макеті ширини більше.
- Запасного шляху для старого сервера без нових колонок немає (за рішенням чату).
- Свайп-жест рядка-підказки — спільний компонент (не змінювався); WebKit-тест перевіряє наявність кнопок і дію «Врахувати» через клік.
- Нових полів вводу, кольорів і статусів не додано.

## Перевірки
- `node --test`, `e2e:smoke` і цільовий WebKit `e2e/mono-refund.spec.js` — підсумки в чаті. Повний E2E не запускався.

## Для iPhone (крок для «Перевірок»)
Стан: Monobank підключено, у «Вхідних» є нове списання і витрата, додана раніше. Дія: дочекатись повернення від продавця (або взяти наявне), відкрити «Вхідні» → «Нові». Результат: списання показує чисту суму, закреслену стару й мітку «Повернено N із M»; повернення без автозіставлення — рядок з міткою-підказкою, свайп вліво дає «Ігнорувати»/«Врахувати», тап по мітці відкриває вибір з запропонованою першою; автоповернення до вже доданої витрати: тост «Повернення N ₴ враховано» один раз, сума в Журналі зменшилась і на другому телефоні; «Пропущені» → рядок повернення → «Скасувати зіставлення» повертає суму.
