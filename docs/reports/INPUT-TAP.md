# INPUT-TAP — Rev 2.32.132 (BUG-INPUT, клас C; не запушено)

Рішення чату: у цьому місці клавіатурну логіку чіпати дозволено; `kb-*`, проміжне поле, стрілки, курсор не чіпались (код підказок поза `initApp`).

## 1. Що знайдено в коді
Обробника, який би **при дотику поза списком сам приймав першу підказку, у коді немає** (перевірено: єдині виклики `selectNameSuggestion` — `handleSuggestionPick` [mousedown і touchend по самому елементу списку] та Enter при підсвіченому пункті; глобальних слухачів `document`/`pointerdown`/`touchstart`, що б вибирали підказку, нема; `blur` лише ховає список через 150 мс). Логу `suggest-pick` перед `pointerdown` я не бачив, тож збіг із ним не підтверджую. Із коду випливають три механізми (гіпотези: на пристрої не відтворено), через які вибір можливий без дотику саме по поточній підказці:
- **Вибір за індексом зі застарілої розмітки.** `touchstart` по елементу списку, потім список перемалювався (автокорекція iOS, повторний фокус, ввід), `touchend` усе одно доставляється старому (відв'язаному) елементу, його `i` вказує на іншу, довшу назву зі свіжого масиву → підміна.
- **Синтезований iOS `mousedown`** після дотику, коли `touchend` не скасовується (інерція прокрутки): він обирає те, що в цей момент під пальцем, а не те, куди тапнули. Захист 400 мс (`lastSuggestionPickAt`) діє лише від повтору вибору, не від такого першого.
- **Повторне відкриття списку:** після вибору короткої `onNameInput()` перемальовує список довшими збігами, а `onfocus` поля назви знову показував його за будь-якого повернення фокуса.

## 2. Виправлення (лише код підказок)
- Покоління розмітки `suggestGen`: вибір дотиком лише з того самого рендера, що й `touchstart`; елемент має бути в DOM; кінець дотику в межах самого елемента й без протяжки (за обома осями).
- Синтезований `mousedown` ігнорується протягом 800 мс після будь-якого дотику (`suggestLastTouchAt`, пасивний слухач); справжня миша працює.
- Дотик/клік поза списком і поза полем назви лише закриває список одразу (capture `pointerdown`, нічого не приймає, подію не гасить: клік по «Додати» доходить до кнопки).
- Після вибору список не відкривається знову, поки користувач сам не змінить текст (`suggestSuppressed`, знімається подією `input`; `onfocus` і програмний `onNameInput` не відкривають).
- Enter при підсвіченому пункті лишається. Форма редагування запису (pointer-події) не змінена.
- Тести: `tests/suggest-tap.test.js` (+6). Живий прогін у браузері на моку: дотик поза списком закрив його, клік дійшов до кнопки; явний тап по короткій підказці підставив коротку назву; повторний фокус список не відкрив.
- Два пристрої, офлайн, синхронізація: не чіпались.

## 3. Два невдалі тапи «Додати» без підказки
Імовірні причини поза списком підказок: (а) `pressStart` ставить `is-pressed` і WAAPI-анімацію на `pointerdown`, а клавіатура, що ховається при тапі, і перерахунок `visualViewport` зсувають кнопку між `pointerdown` і `pointerup`; WebKit не диспетчеризує `click`, якщо відпускання не на тому самому елементі (анімація є, дії немає); (б) зняття `is-pressed` на `pointerup` раніше за `touchend` не є причиною відсутності `click`, лише візуальним симптомом; (в) `addExpense` під `guardEditOpener` при відкритому редагуванні спершу показує підтвердження. Це виправлення (1)–(3 пункти вище) **не покриває**: воно прибирає лише підміну/автоприйом підказок. Рекордер 2.32.129 (`add-button`: `pointerdown`/`pointerup`/`click`/`no-click` із прямокутником) покаже, чи кнопка зсувається; тоді окреме виправлення.

## Для iPhone
- «Витрати»: набрати «Вел», тапнути коротку підказку, одразу «Додати витрату»: додається коротка назва з першого тапу, список після вибору не відкривається знову
- Набрати «Вел», тапнути довшу підказку: підставляється саме довша; дотик по «Додати» поза списком лише закриває список і додає витрату (без прийому першої підказки)
- Прокрутка списку підказок пальцем не обирає підказку
