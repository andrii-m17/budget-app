# LOGIN-RET: вхід по Return у формі входу (Rev 2.32.299, клас C)

Стан: реалізовано, не запушено (чекає слова чату).

## Що змінено
- **Пароль** (`#cloud-password`): `enterkeyhint="go"`, `onkeydown="loginEnterKey(event)"`. Return = `blur()` поля (як дотик по кнопці) і той самий `signInCloudAccount()`.
- **Пошта** (`#cldfielda1`): лише `onkeydown="loginEnterKey(event)"`, **без** `enterkeyhint` у розмітці: явний `enterkeyhint` без `data-kb-enter` змусив би `kbHintsApply` пропустити поле й вимкнув би перевірений шлях клавіатури. Якщо в полі є `data-kb-enter` (iPhone, модуль активний), обробник одразу виходить і перехід робить `kbEnterKey` (поведінка iPhone не змінилась, два обробники не спрацьовують разом). Без мітки (iPad без режиму, десктоп) обробник фокусує пароль з `preventScroll`.
- **Захист від повторного входу:** `signInCloudAccount` став обгорткою з прапорцем `cloudSignInBusy` (`finally`), колишнє тіло це `signInCloudAccountRun` без змін. Return + кнопка, подвійний Return, Return під час входу = один виклик; кнопка «Увійти» під час входу теж ігнорує дотик, її вигляд не змінюється.
- **Не змінювалось:** `id`, `name`, `type`, `autocomplete` (Face ID/автозаповнення пароля), вигляд, тексти, анімація клавіатури, `kbHintsApply`/`kbEnterKey` (охоронний тест), ланцюжок входу й синхронізації; `<form>` не додавався; нових полів і `name` немає.

## Відповіді на ризики
- **Подвійний вхід / Return під час входу:** закрито прапорцем (тести: Return + Return + кнопка = 1 виклик; після завершення вхід знову можливий; прапорець скидається після помилки сервера, мережевого винятку, збою SDK, порожніх полів, офлайну).
- **Face ID:** автозаповнення не генерує `keydown Enter`, тож обробник його не зачіпає; сабміту без дії користувача немає. Перевіряти на пристрої.
- **Порожні поля, офлайн:** повідомлення «Вкажіть email і пароль» / `NEED_NETWORK_TEXT` як і раніше, запиту до сервера немає.
- **IME:** Return зі складанням тексту ігнорується (`isComposing`); Shift/Ctrl/Alt/Meta+Enter теж.

## Після рев'ю і повного E2E
- Повний E2E знайшов єдине падіння: тест 80 (KB-32) свідомо фіксував стару поведінку («пароль не чіпаємо», «Enter на паролі входу не змінює»); оновлено під рішення чату (`enterkeyhint="go"` на паролі; Enter на паролі запускає вхід, порожні поля → підказка).
- Завислий запит без відповіді блокував би повторний вхід до перезавантаження: додано запобіжник `CLOUD_SIGNIN_BUSY_MAX_MS = 20000` (після 20 с прапорець знімається).

## Відхилення і обмеження
- Правило 7 (спершу тест поточної поведінки): тест кнопки (один виклик, порожні поля, офлайн) пройшов і до, і після зміни тіла входу; «до» окремим прогоном на старому коді не знімався (тіло функції збережено дослівно в `signInCloudAccountRun`).
- Фокус із пошти на пароль не через модуль клавіатури (iPad без режиму, десктоп) у самописці може позначитись як `arrow-direct`/`autofill`: лише діагностика.
- `e2e:cloud` для входу не писався (рішення чату); замість нього WebKit-сценарії з підміненим `signInWithPassword`.

## Перевірки
- `node --test`: 2151 тест, 0 падінь, 3 давні `todo` (нових 9 у `tests/login-return.test.js`).
- Повний `npm run e2e` (143 тести, 11,4 хв; `globalTimeout` конфігу 420 с його не вміщає, тому запускався з `--global-timeout=1800000`): 140 пройшло, нестабільні 44 (KB-11) і 45 (KB-12) з відомого списку та сценарій 12 («слова», годинник) пройшли окремо/з повтору, падінь через вхід немає; тест 80 (KB-32) оновлено під Return = вхід.
- WebKit: `e2e/login-return.spec.js`, 3 сценарії: Return у пошті → фокус у паролі без входу; Return у паролі → рівно 1 виклик; Return + Return + дотик по кнопці → 1 виклик, після завершення 2; порожні поля й IME → без запиту.
- Повний `npm run e2e` один раз і `spec-reviewer` один раз: підсумки в чаті.

## Для iPhone (один крок для «Перевірок»)
Стан: вийшов з акаунта, відкрито «Вхід» (профіль), пароль збережено в «Паролях» iCloud. Дія: торкнутись поля пошти → натиснути Return на клавіатурі; потім у полі пароля натиснути Return («Вхід»/Go). Результат: Return у пошті переносить курсор у пароль, Return у паролі виконує вхід рівно один раз (шторка закривається, дані синхронізуються як після кнопки «Увійти»). Окремо: торкнутись поля, дозволити автозаповнення Face ID, переконатись, що обидва поля підставились і вхід НЕ стартував сам, лише після Return або кнопки; після автозаповнення Return у паролі входить один раз.
