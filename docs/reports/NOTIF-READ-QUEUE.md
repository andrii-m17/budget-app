# NOTIF-READ-QUEUE (клас C, Rev 2.32.147)

## Підсумок
Офлайн-тап по сповіщенню тепер лишається прочитаним: id ставляться в локальну чергу (`budget_notif_read_queue_v1`, `{uid, ids}`), рядок і лічильник прочитуються локально, відправка одним `mark_notifications_read({p_ids})` за паузами 30/60/120 с (4 невдачі зупиняють; далі лише `online`/`visible` раз на хвилину).

## Зроблено
- WIP збережено на гілці `wip/notif-read-queue`; червоні тести виправлено без послаблення вимог: ключ черги в `accountLocalStorageKeys`; код черги винесено перед блок Monobank (охоронний тест MB-3 цілий); стаби `notifQueueAdd`/`notifFlush`/`monoReady`/`notifEffectiveUnread` оновлено.
- Холодний старт: порожня черга → жодного запиту (тест `sync-check` без змін у числі запитів).
- «Прочитати всі»: офлайн — явні id в чергу; онлайн-помилка сервера — як було (тост).
- Константу стану перейменовано `NOTIF_FLUSH_STATE` (екстрактор тестів розпізнає const за великими літерами).

## Зауваження spec-reviewer
- Зауваження `spec-reviewer` (виправлено): збій запису в сховище після успішної відправки рахується невдачею з паузою (не негайний повтор); видалення/«Очистити» прибирають id з черги; без `uid` тап не позначає прочитаним локально; знімок черги на старті `loadNotifArchive` проти застарілої відповіді. Прийнято без змін: лічильник «голів», запитаних до успіху flush, може миттєво завищитись до наступного оновлення; id, уже прочитані на сервері іншим пристроєм, тимчасово занижують лічильник до успішної відправки; черга чиститься і при «видалити всі дані»; ліміт 500 (практично недосяжний). Тест на знімок черги в `loadNotifArchive` не додано (лише код). Тестів 1578.
