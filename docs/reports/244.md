# Rev 244 (застосунок 2.32.242, ID-ONLY): ОЧ впізнається лише за id (клас C, запушено)

## Що зроблено
- Спільний механізм у `index.html` біля `planInstallmentAccountsPush`: `idOf`, `idEnsureClientId`, `idMatchKey`, `idMigrateUnlinked(client, spec)`, `idSendNew(client, spec, rec, userId, id, getFirst)`. ОЧ підключена через `installmentIdSpec()`; у 245 картки, категорії, підкатегорії й слова лише дадуть свій spec (таблиця, ключ зіставлення, payload).
- `pushInstallmentAccountsPilot`: міграція → для кожного запису id є до мережі (`clientId`, збережений локально) → `insert` з клієнтським id; 23505 → GET за id (живий: оновлення; надгробок: `pullAccountTombstone`, нового рядка нема); помилка = `anyError`, без `insert`; підтверджений `cloudId` зберігається після кожного запису. Для запису з `cloudId`, якого `update` не знайшов, GET за id: немає рядка → `insert` з тим самим id; живий → помилка, не вставляємо.
- `reconcileInstallmentAccountCloudId` видалено. `byName` у `pullInstallmentAccountsCore` прибрано; додано зв'язування `clientId → cloudId`, якщо рядок із таким id уже на сервері; перед pull виконується та сама міграція.
- Перепис id (`reconcileAccountsCensusFor`, параметр `keepId` лише для ОЧ): рядка нема на сервері → id лишається за записом, рядок піднімається тим самим id.
- Гілка без `serverBase` шле `name` тільки при `nameDirty` (виставляється в `saveInstallmentDrawer` і при прибиранні emoji).
- Нова ОЧ (`addInstallmentAccount`) одразу дістає `clientId`. Мок хмари: 409/23505 на дубль ключа; `tests/extract.js` дає `window.crypto`.

## Відхилення від плану
1. Окреме поле `clientId` замість присвоєння `cloudId` до мережі: інакше борги й витрати шлють FK на ще не існуючий рядок, і самолікування 23503 скидає id. Ефект для користувача той самий (id збережено до мережі, вікно «рядок є, id невідомий» закрите).
2. Пункт плану про непотрібність `invalidateAccountChildren` у переписі id не виконано: виклик лишено (безпечний, діти просто пере-надсилаються).

## Правила міграції (записи без жодного id)
Ключ: `created_at` до мілісекунди + `initial_amount`. Один кандидат (і один локальний запис із таким ключем) — зв'язати. Нуль — новий id, `insert`. Два й більше — запис лишається локальним, подія `och-ambiguous` (лише кількість). Три пари дублів: обидва рядки мають однаковий ключ, тож зв'язування «навмання» не відбудеться.

## Ризики
- Записи без id й без `created_at` (імпорт Excel, старі дані) зіставити неможливо: вони стануть новими рядками. Для записів з відомим `cloudId` нічого не змінюється.
- Сума, змінена на старому пристрої до міграції, ламає ключ: запис вважатиметься новим (нуль кандидатів) і створить рядок поруч. Лише для даних, де id втрачено ще до цієї ревізії.
- Старий клієнт на іншому пристрої до оновлення діє за старими правилами.
