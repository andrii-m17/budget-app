## Крок 0: де колір і коли заповнюється автор
- Колір: Журнал → `authorFrameColorVar(e.createdBy)` (раніше `authorInfoFor`, який без довідника користувачів повертав null).
- Автор запису: у `addExpenseCore` не виставлявся; з'являвся лише з рядка сервера в `pullExpensesCore`.
- Розриви: (1) pull, гілка «локальна новіша» (за годинником пристрою) → `continue` без автора, навіть коли запис уже надісланий; мітка просувалась, дельта після перезапуску рядок не повертала; (2) довідник користувачів — мережею; на слабкому зв'язку порожній → без рамки, хоч стать у кеші; (3) нічого не донаповнювало вже створені записи без автора.

## Зроблено
1. `localAuthorId()`: автор ставиться локально в момент створення (сесія, без запиту), записується в сховище → переживає перезапуск. `created_by` у push не додається, pull перезаписує серверним, якщо відрізняється.
2. Pull витрат: clean-запис «новіший» за годинником → приймається серверний рядок (автор, `updated_at`), без повторного push; unsynced-новіший → вміст лишається, автор донаповнюється.
3. `authorFrameColorVar`: довідник або кеш статі (кольори/CSS-змінні ті самі).
4. `backfillExpenseAuthors`: одноразово при вході, лише id без автора, пакетами по 100, без повного перезавантаження; прапорець після повного успіху; очищається при виході.
