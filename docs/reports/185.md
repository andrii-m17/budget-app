# Rev 2.32.185 — ID-BIND-3 (Етап 3): ОЧ за id

Не запушено до слова чату. Сервер не чіпався; серверні об'єкти (`sync_debt_names_on_installment_rename`, `trg_sync_debt_names`) описано в `docs/SUPABASE_POLICY.md`.

## Зроблено
1. Перейменування у формі ОЧ: `cascadeInstallmentRename` (за `accountId`, запасний варіант — назва): усі місяці боргів, витрати, `ignoredDivergences`, ключі приховування. Борги не пушаться (`updatedAt`/`syncedUpdatedAt` не змінюються), `saveDebts`/`saveExpenses` лише локальні.
2. Борг місяця: `findAccountMonthDebt` (id → назва) при відкритті шторки й збереженні; новий борг несе `accountId`. Борг іншої ОЧ з тією ж назвою не береться.
3. Push боргів і витрат: `debtOwnerAccount` / `linkedOwnerAccount`; у payload назва рахунку; без знайденої ОЧ — `{success:true, unresolved:true}`, запис лишається непушнутим і видимий у діагностиці «незапушені записи».
4. Видалення/purge: `purgeAccountPlan` / `removeAccountFromState` за записом (cloudId, id боргів і витрат, `hiddenKeys`); при двох ОЧ з однаковою назвою записи без id не чіпаються.
5. Приховування ОЧ: ключ `installment:#cloudId`; `hiddenEntryFor` читає id → назву → `accountName`; `rekeyHiddenFrom` мігрує при pull ОЧ; pull і push hidden_entities розуміють ключі за id. **Зміна сервера не потрібна** (`hidden_entities.entity_id` уже `cloudId`).

## Тести
`tests/id-rename.test.js`: (а) перейменування при боргах у кількох місяцях, (б) збереження форми зі застарілою назвою без дубля, (в) перейменування без push боргів і без зміни `updatedAt`; ключі приховування (id, сумісність, self-heal, rekey), push за id, purge за записом. Охоронні: нових полів у push нема, формули залишку без змін. Усього 1810, 0 помилок.

## Відхилення і ризики
- Картки лишились на ключах приховування за назвою: завдання про ОЧ; перейменування карток має окремий шлях.
- Старі тести про `hideKey`-ключі й `{success:true}` оновлено (нова поведінка: `unresolved`, ключі за id).
- Борги без `accountId` і без збігу назви (осиротілі) за поточною логікою лишаються непушнутими; це не втрата, але їх треба розбирати вручну.

## Не перевірено
Реальні дані, два пристрої на справжньому сервері з тригером, повна синхронізація hidden_entities після міграції ключів. На iPhone: перейменувати ОЧ з боргами в кількох місяцях і перевірити, що другий пристрій після sync бачить нову назву скрізь; приховану ОЧ лишається прихованою після перейменування.
