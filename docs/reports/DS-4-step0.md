# DS-4 · Крок 0: шторки без «×», закриття свайпом, відступи у формах (клас C, лише читання)

Нічого в коді не змінено. Докази: `index.html` (розмітка шторок, `initDrawerSwipeToDismiss` ~19868, Esc ~19858, `closeX`-функції, `focusFirstIn`/`js/shell.js:1488`), `css/app.css` (`.drawer` 1818–1990, `html.kb-sheet .drawer.open` 1936, десктоп ≥ 1280 ~2733), макет `docs/ui/mockups/analytics-ds/index.html` (`.sheet-top`, жест ~941), `docs/specs/DS-PLAN.md` (розділ «Шторка»), `scripts/ds2-apply.js --sp --dry` (винятки DS-N4b), `docs/reports/STRUCT-3-step0.md`, `docs/PLATFORM_LIMITS.md`.

## 0. Підсумок і рекомендація

1. Перед DS-4 **нічого великого переносити не треба**: жест шторок уже в глобальній області (поза `initApp`), для клавіатури достатньо CSS-змінних і класів. Рекомендую лише дрібний перенос коду жесту в `js/sheets.js` (клас A, дослівно) як перший крок. `sheets-forms` (STRUCT-3g) і STRUCT-4 для DS-4 не потрібні (§5).
2. **Три знахідки, важливі вже зараз:** (a) свайп за смужку в `#struct-drawer` не працює (обробник клікає `.drawer-close`, а там її немає); (b) поточний свайп ставить інлайн `transform` і на мить стирає підйом від клавіатури (`--sheet-lift`) — із відкритою клавіатурою буде стрибок; (c) якщо «×» прибрати через `display:none`, `focusFirstIn` віддасть фокус першому полю й підніме клавіатуру при відкритті (порушення `ios-keyboard-safety`) — «×» має лишитись у розмітці візуально прихованою.
3. Закриття шторки з формою **зараз завжди мовчки відкидає зміни** (захист прибрано в Rev 2.16.6). Свайп робить випадкову втрату легшою, тож пропоную підтвердження лише коли форма змінена (механізм змін уже є — save-gate). Потрібне ваше рішення.
4. Рекомендований порядок: DS-4a0 (A) → DS-4a (C, жест) → DS-4b (C, без «×») → DS-4d1 (A/B, відступи на сітці) → DS-4c (C, підтвердження) → DS-4d2 (B, ±2 px після погодження).

## 2. Жест

### 2.1 Як є зараз
- `initDrawerSwipeToDismiss` (`index.html` ~19868, глобальна область, **поза `initApp`**): слухачі лише на `.drawer-handle` (`touchstart/move/end` і `pointer*` одночасно — обробники виконуються двічі на дотик), поріг 90 px, швидкості немає; відпускання вище порога клікає `.drawer-close`; під час руху інлайн `drawer.style.transition='none'` і `drawer.style.transform='translateY(dy)'`; затемнення не слідує; смужка 36×4, `touch-action:none`; на ≥ 1280 смужка прихована.
- Тестів поведінки свайпу немає (`e2e/keyboard.spec.js:1676` лише імітує `touchstart` на смужці профілю для «touch-cancel»).

### 2.2 Макет
`.sheet-top` = смужка 36×5 (радіус 3) + заголовок: тягнути можна за обидва; закриття при зсуві > 110 pt або при швидкості > 0,6 px/мс і зсуві > 30 pt; під час руху шторка іде за пальцем, затемнення слабшає (`1 − r/400`); перехід `--t-l` + `--ease-out`; Esc і дотик по затемненню. Геометрія макета: шторка на всю ширину, прикріплена до низу, радіус зверху `--r-xl`.
**Розбіжність із застосунком:** у застосунку шторка — «плаваюча картка» (відступи 16 з боків, `bottom: var(--drawer-bottom-base)` ≈ 100 px, радіус з усіх боків, рішення 6D.11). Змінювати геометрію я не пропоную (від неї залежить розрахунок клавіатури) — потрібне ваше погодження, що жест і «без ×» робимо на нинішній геометрії.

### 2.3 Як поєднати зі скролом вмісту
Шторка сама є контейнером прокрутки (`overflow-y:auto; overscroll-behavior:contain`), усередині поля й підказки.
- **Рекомендую (як у макеті):** жест лише за смужку й заголовок; заголовок отримує `touch-action:none` (у горизонтальній орієнтації й при клавіатурі він `position:sticky`/`static`, зону треба рахувати за фактичним положенням).
- Не рекомендую: свайп із вмісту, коли прокрутка нагорі — конфлікт із прокруткою, полями й панорамою клавіатури; можна розглянути окремо після пристрою.

### 2.4 Клавіатура (`kb-*`, Баг 1, безпечна зона)
- Підйом шторки задає CSS (`html.kb-sheet .drawer.open { transform: translate3d(0, calc(-1px * var(--sheet-lift)), 0); transition: transform var(--kb-dur) var(--kb-ease) }`, css 1936). Нинішній інлайн `transform` свайпу **перекриває підйом** на час жесту, а `''` після нього повертає — з відкритою клавіатурою це дає стрибок.
- Варіанти: (1) **під час `html.kb-sheet` жест вимкнено** (закриття затемненням/Esc; без змін у `kb-*`) — рекомендую для першої ітерації; (2) скласти зсув у тому самому `transform` через змінну `--sheet-drag` (змінює правило клавіатури, клас C, потрібні клавіатурні набори й пристрій). Закриття під час клавіатури має йти через звичайні `closeX` → `planSheetClose`, не через прямі стилі.
- Фокус при відкритті — на контейнері (`tabindex=-1`), не на полі (див. §3).
- Системна смуга біля країв (≈ 15–20 px): жест вертикальний усередині картки; горизонтальні краї не задіяно; низ картки ≥ ~100 px від краю (смужка «home» окремо); верх шторки нижче `safe-area-inset-top` + 12 px — тобто смуга й верхній край не заважають.
- **iPad:** < 1280 пт (портрет, у т.ч. дотик) — та сама нижня картка зі свайпом. ≥ 1280 пт (десктоп, iPad Pro в альбомі) — права панель 360 px (`translateX`), смужка прихована, свайпу немає; із дотиком «×» там єдиний видимий спосіб (крім затемнення). **Пропозиція:** на ≥ 1280 «×» лишити видимою до окремого етапу «десктопна версія DS».
- **Десктоп:** Esc і клік по затемненню (є). Виправити «Esc закриває все» → лише верхню (частина DS-4c).
- **«Зменшити рух»:** слідування за пальцем лишається (пряма маніпуляція), перехід закриття/повернення миттєвий (глобальне правило застосунку 80 мс).

## 3. Доступність без «×»

Є: `role="dialog"`, `aria-modal="true"`, `aria-label`, `inert` у закритому стані, `focusFirstIn` (кнопки → фокус на контейнер), `restoreFocus`, `lockBackgroundScroll`, Esc; «×» має `aria-label="Закрити"`.
Пропозиція (не змінює порядок фокусу й клавіатуру):
1. «×» **лишається в розмітці**, першою в заголовку, з класом візуального приховання (sr-only: 1 px, `clip`, **не** `display:none`/`visibility:hidden`): її бачать VoiceOver, Switch Control, Tab; код, що викликає `.drawer-close.click()`, не ламається; `focusFirstIn` бачить кнопку (`offsetParent !== null`) і ставить фокус на контейнер, а не на поле.
2. При `:focus-visible` (зовнішня клавіатура) кнопка показується як капсула «Закрити» біля заголовка.
3. Смужка лишається `aria-hidden`; для `struct-drawer` додати таку саму приховану «Закрити» (зараз немає жодної) і виправити свайп.
4. Esc, фокус назад на елемент, що відкрив шторку, `aria-modal` — без змін.
5. VoiceOver-жест «Escape» (двопальцевий Z) на веб-вмісті: чи генерує він `Escape` у Safari PWA — перевірити лише на пристрої (з Code не перевірити). Прихована «Закрити» є запасним варіантом.
6. На ≥ 1280 пт «×» лишається видимою (див. §2.4).

## 5. Перенесення коду

| Питання | Висновок |
|---|---|

| DS-4d2 | B | Відступи ±2 px → сітка (по групах, без ОЧ і `kb-sheet`) | сітка DS | кожна група зі знімками «до/після» |

Порядок: a0 → a → b → d1 → c → d2. Кожна ревізія клас C — клавіатурні набори зачепленої області; пуш лише після «можна пушити».

## 8. Ризики коротко

1. Конфлікт інлайн-`transform` із підйомом клавіатури (§2.4).
2. `display:none` на «×» → фокус на полі → клавіатура при відкритті (§3).
3. `struct-drawer` без «×»: свайп не працює, потрібен окремий закривач.
4. Esc закриває все одразу (стек діалогів).
5. Подвійні обробники touch+pointer; `touch-action:none` на заголовку не має вимкнути дотики по вмісту заголовка.
6. Липкий заголовок у альбомі/клавіатурі: зона жесту = фактичний `.drawer-head`.
7. Геометрія макета (на всю ширину) ≠ плаваюча картка застосунку — не змінюємо без погодження.
8. VoiceOver-поведінку Esc з Code перевірити неможливо.

## 9. Питання до вас

1. Підтвердження при закритті зміненої форми (варіант B) — так/ні, і які шторки покривати.
2. На ≥ 1280 пт «×» лишаємо видимою до етапу десктопа — так?
3. При відкритій клавіатурі свайп вимкнений (варіант 1) — підходить?
4. Геометрія шторки лишається плаваючою карткою; смужка 4 → 5 px — погоджуєте?
5. Відступи: DS-4d1 (на сітці) одразу; DS-4d2 (±2 px) — після знімків по групах, без ОЧ і `kb-sheet`.
