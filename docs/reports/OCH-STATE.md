# OCH-STATE (клас B, Rev 2.32.151)

## Підсумок
Стан платежу ОЧ у місяці (✓, ½, «скоро», «!») за сумою прив'язаних витрат і очікуваним платежем; єдина чиста логіка `installmentPaymentState` / `installmentPaidFull` / `installmentExpectedPayment` для рядка «Обліку» й «Найближчих платежів».

## Матриця сценаріїв (tests/och-state.test.js)
| Сценарій | Очікування |
|---|---|
| сума ≥ очікуваного, допуск max(2 ₴, 1%) | ✓; більше допуску: «внесено більше» |
| часткова, до дати > N | ½ «Частково: X з Y ₴» |
| нічого не внесено, до дати > N | без значка |
| до дати = N і N−1; день платежу; дата+1 | «скоро» |
| дата+2 і далі, не повністю (включно з нулем) | «!» |
| попередній місяць, не повністю | «!» завжди |
| місяць старший за попередній / майбутній | без значків |
| без `dueDay` | без «скоро» і «!» (½ лише при частковому) |
| очікуване невідоме | будь-яка сума = ✓; нуль → за датою |
| останній платіж | очікуване = залишок, якщо менший |
| кілька внесків | сума; у «Найближчих»: повні зникають, часткові лишаються |
| N = 0, 7, відсутнє/некоректне значення | 0, 7, 2 |
| приховані ОЧ | не в «Найближчих платежах» |

## Вплив
- «Найближчі платежі»: «сплачено» = сума ≥ очікуваного; часткова лишається в списку (сума й оцінка без змін) і може потрапити в «N без позначки».
- Крапки неповних даних: без впливу. Формули оцінки залишку не змінено.

## Відомі обмеження
- N = 2, поки екран «Сповіщення» не відкривали в сесії (додатковий запит не робимо).
- Входи очікуваного в рядку й у «Найближчих» збираються окремо (різне джерело залишку: `lastKnownBalance` з урахуванням приховування проти запису історії); єдиний збирач можна винести окремою ревізією.
- Рендер рядка перевірено знімком і текстовими перевірками, поведінкового тесту DOM немає.
- Знімок «до» не знято (раніше значка не було).

## Не перевірено, для iPhone
½, теплий акцент за N днів, «!» на дата+2, ✓ і «внесено більше»; читабельність «½» у бейджі 16 px.
