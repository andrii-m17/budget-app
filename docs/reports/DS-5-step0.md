## 4. Нові розрахунки

Усі функції чисті (без DOM і глобального стану), щоб тестувалися через `tests/extract.js`; імена додати до списків тестів (CLAUDE.md, розд. «Архітектура»). Усі суми цілі гривні; відсотки відображення округлюються `Math.round` до цілого.

### 4.1 `dayBarModel` (DS-5a)
Вхід: `spent`, `income`, `N`, `T` (0..N, 0 = ще не почався, N = завершений).
- `S = spent / income × N` (скільки днів «з'їли» витрати). Сегмент d (1…N) заповнений на `clamp(S − (d−1), 0, 1)`.
- Колір заповнення: сегмент ≤ T синій, > T бурштиновий (випередження). Незаповнене до T: світло-зелене.
- `diff = round100(spent − income × T / N)`. Це алгебраїчно те саме, що `(spent/income − T/N) × income` з ТЗ, але без ділення на `income`. Рекомендую саме цю форму.
- `round100`: симетричне округлення (`sign × Math.round(|x| / 100) × 100`); не `Math.round(x/100)*100`, бо `Math.round(−1,5) = −1` (зсув до +∞) дає асиметрію для від'ємних.
- Підпис: `diff > 0` — «Витрати на {diff} випереджають дні» (бурштин); `diff < 0` — «… менші, ніж минуло днів» (зелений); `diff = 0` (|значення| < 50) — «йдуть у ногу з днями».

Приклад: дохід 42 000, витрати 23 600, N = 30, T = 16 → `S = 16,857` (16 повних сегментів + 86 %), `diff = round100(23 600 − 22 400) = +1 200`, риска на 53,3 %.

| Межа | Поведінка (пропозиція) |
|---|---|
| Дохід 0 / немає | смуги немає, лише порожній трек; підпис «Немає доходів за місяць»; `diff` не показуємо |
| Витрати > дохід (`S > N`) | усі N заповнені; підпис «Витрати перевищили дохід на …» (замість темпу); залишок від'ємний, колір помилки |
| Витрати 0 | порожня смуга, `diff = −income × T / N` («на … менші») |
| Минулий місяць | `T = N`, без риски й «сьогодні», підпис «Місяць завершено: витрачено X % доходу» |
| Наступний місяць | `T = 0`, без риски, «Місяць ще не настав»; дані зазвичай порожні (перемикач дозволяє `nextKey`) |
| Перший місяць даних | як звичайний; порівняння з минулим «—» |
| Неповні дані (дохід внесено частково: одна з двох зарплат) | `S` завищена; це обмеження самої формули, у підпис не виносимо; позначення неповних даних лише за наявними правилами крапок |
| Записи з датою пізніше за T у цьому місяці | входять у `spent`/`income` місяця (як зараз у KPI); у порівнянні «на той самий день» не входять |

### 4.2 `sameDayTotals` (DS-5a)
Визначення: для обраного місяця `T` — сума записів із днем ≤ T; для минулого місяця — з днем ≤ `min(T, N_prev)`.
Відсоток `round((cur − prev) / prev × 100)`, лише при `prev > 0`, інакше «—» (не «∞»).
Приклад: витрати до 16-го: 23 600 (зараз), 27 100 (минулий) → `−12,9 %` → «−13 %»; доходи 42 000 / 39 500 → «+6 %».

| Межа | Поведінка |
|---|---|
| T = 31, минулий місяць має 28/29/30 | прирівнюємо до останнього дня минулого |
| T = 1 | лише записи першого числа |
| Минулий обраний місяць | порівняння повного місяця з повним попереднім (`T = N`) |
| Попередній місяць порожній / це перший місяць | «—», підпис «на 16 жов: —» |
| `prev = 0`, `cur > 0` | «—» (не нескінченний відсоток) |
| Дохід «до дня T» менший за поточний через майбутні дати | порівнюємо однаково для обох місяців |

### 4.3 «≈ … на день після обов'язкових» (DS-5a)
`perDay = round10(max(0, freeMoney) / (N − T + 1))`; знаменник включає сьогодні (у макеті 16 700 / 15 = 1 113 → «1 110»).
Розбіжність: макет у рядку смуги пише «14 днів лишилось» (`N − T`), а на цю суму ділить на 15. Потрібно одне визначення (Q1).
| Межа | Поведінка |
|---|---|
| `freeMoney ≤ 0` | «≈ на день» не показуємо; «решта» стає «перевитрата …» |
| Минулий місяць | підказка «решта …» (без «на день») |
| T = N | знаменник 1 |
| Наступний місяць | без «на день» |

### 4.4 `ochPaidFraction` (DS-5b)
`paid = Σ(initial_i − balance_i) / Σ initial_i` по **активних** ОЧ із відомою `initialAmount > 0`; кожне значення клампиться до 0..1.
- Активна: залишок > 0 (завершені не входять у знаменник; зараз `activeOch` рахує й нульові записи, це треба вирівняти).
- ОЧ без `initialAmount`: виключаємо з чисельника й знаменника; якщо виключені є, у плитці синя крапка «неповні дані» (правило крапок із DS-PLAN розд. 1), смуга по решті. Якщо відомих немає, смуга й «%» не показуються.
- Залишок > початкової (хибні дані): частка цього ОЧ 0, не від'ємна.
Приклад (вигадані): початкові 189 780, залишок 109 160 → `42,5 %` → «42 %» (`Math.round(42,48)`).

### 4.5 `cardUsage` (DS-5b)
`usage = balance / creditLimit`, смуга клампиться до 100 %, текст «N % використано» показує реальне значення (може бути > 100 %).
| Межа | Поведінка |
|---|---|
| `creditLimit` `null` / 0 | смуги й «%» немає, «кредитний ліміт не вказано» + крапка (`code: 'limit'` вже є у `incompleteReasons`) |
| Борг 0 | «без боргу», смуга порожня, сума приглушена |
| Борг > ліміту | смуга повна, «112 % використано» |
| Картка прихована для місяця | не показується (як `isAccountHiddenForMonth`) |
Дельта на плитці «Борг» («−8 200 ₴ від жовтня») лише при `cardDeltaKnown`; інакше «Станом на {місяць}» і крапка (правило §3.1; у макеті цього немає).

### 4.6 `donutModel` (DS-5c-1)
Вхід: список `{name, sum, emoji, parent}`, режим (категорії/підкатегорії). Частка `L = sum / total × 100`; підпис на секторі при `L ≥ 7`; відступ між секторами 0,8 (макет: `L − .8`, мінімум 0,3).
| Межа | Поведінка |
|---|---|
| Усі витрати в одній категорії (`L = 100`) | один суцільний сектор без відступу (з відступом 0,8 лишилася б щілина) |
| Сума 0 / немає витрат | порожнє кільце, центр «Немає витрат», шторку не відкриваємо або відкриваємо з порожнім станом |
| Більше за 6 категорій | кільце: топ-5 + «Інші»; кольори `--k1…--k6`; у списку шторки всі (Q3) |
| Підкатегорії | топ-9 + «Інші» + (за Q3) «Без підкатегорії»; відтінок = колір батька × 100/64/42 %; більше трьох підкатегорій в одного батька: 4-а і далі 42 % |
| Підкатегорія одночасно під двома категоріями | батько = категорія з більшою сумою |
| Запис без категорії | «🧾 Без категорії», як зараз |
| Два сусідні сектори по 7 % | відстань між центрами підписів ≈ 35 pt (R = 80,9; кут 25,2°), підпис «👕 7 %» ≈ 30 pt: на межі, перевірити знімком |

Приклад: 6 900 / 23 600 = 29,2 % → «29 %».

### 4.7 `discretionarySet` і `typicalMonth` (DS-5c-2)
- Необов'язкові витрати місяця = Σ витрат підкатегорій, що мають запис у `SUBCATEGORY_PRIORITY` (множина — Q2).
- Типовий місяць: беремо **6 повних місяців перед обраним** (поточний або обраний не входить; місяці до `earliestActivityMonth` виключаємо, а не рахуємо нулями); сортуємо, прибираємо найбільший і найменший, середнє решти, округлення до 100; менше 3 місяців → просте середнє + позначка «мало даних»; `рік = 12 × типовий`.
- Порогові випадки, що в ТЗ неоднозначні: рівно 3 місяці після відкидання лишають **одне** значення (медіану); 4 → два. Запропоновано лишити як у ТЗ, але підтвердити (Q9).
- Нулі: місяць із даними, але без «необов'язкових», рахується як 0 (це реальний факт); місяць без жодного запису — виключається. У макеті `filter(x > 0)` стирає обидва випадки, тому в код його переносити не можна.
- Пріоритети — **поточні** налаштування, не історичні: зміна пріоритету перераховує й минулі місяці. Це свідомо, але варто написати у звіті.
Приклад: 4 200, 5 100, 7 900, 4 600, 4 900, 5 400 → без 4 200 і 7 900 → 4 600, 4 900, 5 100, 5 400 → середнє 5 000 → «≈ 60 000 ₴ на рік».
| Межа | Поведінка |
|---|---|
| Перший місяць даних | немає попередніх: «≈ на рік» не показуємо, лише суму місяця |
| 1–2 місяці | просте середнє, «мало даних» |
| Минулий обраний місяць | вікно — 6 місяців перед ним |
| Немає підкатегорій з пріоритетом | картка з порожнім станом «Немає підкатегорій для аналізу» (текст є) |

### 4.8 `niceAxisStep` (DS-5d-1)
`step` = перший із `[5k, 10k, 20k, 25k, 40k, 50k]` такий, що `max / step ≤ 4`; далі за схемою 1–2–2,5–5 × 10^k (у макеті стрибок 100k → 200k). `axisMax = max(step, ceil(max / step) × step)`.
- Знайдений дефект макета: при `max = 0` (усі нулі) `axisMax = 0` і висота `1 − v/0` дає NaN. Потрібне `max(step, …)`.
Приклади: 51 000 → 20k (3 інтервали, вісь до 60k); 9 000 → 5k (вісь до 10k); 0 → 5k (вісь до 5k).
Підписи «Nk»: ≥ 1 000 → `Math.round(v/1000) + 'k'`; менше 1 000 — повна сума (макет показав би «0k» для 400 і «1k» для 700).
Поточний місяць напівпрозорий лише якщо це **поточний** місяць (`T < N`); для минулого обраного місяця стовпчик повний.

## 5. Розбіжності ТЗ / макета / коду

1. **Обов'язкові > витрат.** Макет: обов'язкові 25 300, усього витрат 23 600. За визначенням (`mandatoryPaymentsSummary`, FINANCIAL_RULES §2) обов'язкові — підмножина внесених витрат, тому не можуть бути більшими. Або макет містить очікувані платежі (тоді це нова формула, що чіпає §3.2), або дані макета вигадані неузгоджено. Рекомендація: формулу не міняти, у макеті виправити числа.
2. **Дельта боргу без перевірки факту** («−8 200 ₴ від жовтня»): у коді перевірка `cardDeltaKnown`. Макет треба доповнити станом «Станом на …».
3. **Лінія боргу в макеті суцільна**, у коді розриви для місяців без факту (§3.1). Зберегти розриви.
4. **Знаменник відсотків:** макет — частка витрат; код — частка доходу (рядки таблиць, `analytics.js:1083`). Змінюємо на витрати (кільця вимагають суму 100 %); потрібне підтвердження, бо це зміна показника.
5. **«Інші» й «Без підкатегорії»:** макет бере «Інші» як решту, у коді підкатегорії без значення свідомо не рахуються (Rev 1.3.1). Для суми 100 % потрібен сегмент «Без підкатегорії».
6. **Висновки:** ДС-план для DS-5d каже «лише іконки», макет показує інший набір з трьох висновків («третій місяць поспіль», «менші, ніж на 16 жовтня» — нові формули).
7. **Наступний місяць:** план каже «майбутні місяці недоступні», код `monthPickerList` додає наступний (`shell.js:5–13`). Це поза DS-5, але впливає на T = 0 у смузі днів і на порожні картки.
Дрібніше: у макеті є невикористані `PACE` і `PROJ2` (прогноз місяця) — у коді їх не реалізуємо; «Найближчі платежі» зараз перші, у макеті другі; десктоп у DS-5 не охоплений (нові картки на ≥ 1280 лишаються вузькою колонкою, окрема версія після DS-5).

## 6. Графіки й взаємодії

### 6.1 Що перевикористовується
- `svgBarChart`, `svgLineChart`, `chartSignature`/`shouldReplaceChart` (заміна вузла лише при зміні підпису даних), `setDashChart` — основа лишається, змінюються розмір (212 pt), шкала й підписи; `totalSlots=6` вже підтримує «дані зліва».
- `ochOvalsModel`/`ochOvalsHtml` для смуги ОЧ у шторці (овали замість сегментів, k з n).
- Сегмент (40 pt, ковзний індикатор), шторка `.drawer` + `SHEET_CLOSERS` (DS-4), розгортання grid-rows.
- Спарклайн `svgSparkline` не підходить (немає виділення точки): потрібна `lineChart` з макета (h = 38).
- Не перевикористовується: кільце `renderDebtDonut` (замінюється смугою), «овали» старої картки ОЧ у компакті.

### 6.2 Дотик і ведення пальцем (динаміка, спарклайни)
Макет: `pointerdown/move/up` на контейнері, `touch-action: pan-y` (рядок 248 макета) — це ключове: вертикальна прокрутка сторінки лишається, горизонтальний рух віддається графіку. Місяць = `floor((x − pl) / gw)` з клампом 0..5; смуга `band` і лінія `vl` рухаються через атрибути, решта приглушується класом (`opacity`); легенда змінюється текстом.
Ризики для застосунку: (а) глобальні слухачі `pointerdown/up/move` у `initPressFeedback` (capture), їх треба перевірити на конфлікт; (б) жест від краю (резерв iOS 15–20 pt, CLAUDE.md): перший стовпчик за `pl = 34`, тож зона безпечна; (в) `pointercancel` при початку прокрутки скидає вибір: вибраний місяць лишається до наступного дотику поза графіком (макет скидає лише дотиком без руху); (г) VoiceOver: контейнер з `role="img"` не дає доступу до окремих місяців; запропонувати прихований список `<ul>` із сумами (текстовий еквівалент) — решту лишити як у макеті.

### 6.3 Кільця
Реалізація макета: окремі `circle` з `stroke-dasharray` (анімація довжини дуги 800 мс; це не `transform`/`opacity`, а властивість SVG-штриха. Узгодити з правилом «рух лише transform/opacity»: або виняток для штриха, як уже зроблено для старого кільця боргу через rAF, або `clip` через `transform: rotate`/`scale` сегмента; Q10). Підписи секторів — HTML `span` поверх SVG (позиція за кутом, `R = 80,9`). Центр — `<button>` («знімає вибір»). Вибір: клас `dim` на решті; дотик сектора, рядка, центру. Режими мають **окремі** кільця (перемикач над кільцем, `catMode`), стан вибору скидається при зміні режиму й місяця.

### 6.4 Шторки на компоненті DS-4
Три нові: `debt-sheet`, `inst-sheet`, `cats-sheet` (id за схемою без підрядків із правил автозаповнення: полів вводу в них **немає**, лише перегляд, як у `checks-drawer`/`trash-detail-drawer`). Для кожної: розмітка `.drawer` у `index.html`, функції відкриття/закриття, запис у `SHEET_CLOSERS`, перевірка Esc, затемнення, свайпу вниз за смужку/заголовок, блокування прокрутки під шторкою. Клавіатурний конвеєр не чіпаємо. `sheets-close.spec.js` і `sheets-swipe.spec.js` перелічують шторки, їх доведеться розширити. Дані шторки перемальовуються з моделі при кожному `renderDashboard`, поки вона відкрита (два пристрої, Realtime); вибір у кільці скидається, якщо його пункт зник.

## 7. Продуктивність

Виміряно на синтетичних даних у Node (однопоточно, прогрів, 200 повторів; **не** на iPhone): вісім викликів `monthAggregates` (як нині) проти одного проходу, що збирає суми по місяцях:
| Витрат | Поточний підхід (8 агрегацій) | Один прохід |
|---|---|---|
| 120 | ≈ 0,02 мс | ≈ 0,01 мс |
| 5 000 | ≈ 0,83 мс | ≈ 0,18 мс |
| 20 000 | ≈ 3,3 мс | ≈ 0,69 мс |

Нове навантаження: порівняння «на той самий день» (2 місяці), типовий місяць (6 місяців) і підсумки по категоріях. Усе це можна отримати з одного проходу (`buildMonthIndex`: суми по місяцях, по днях двох місяців, по категоріях і підкатегоріях, необов'язкові по місяцях). Кешування за версією даних не потрібне: вартість нижча за один кадр і далека від вузького місця. Реальні витрати — DOM: перемальовування SVG (графіки замінюються лише при зміні `data-sig`, механізм лишаємо), побудова шторок лише при відкритті.
Рекомендація (необов'язкова): не викликати `renderDashboard`, коли вкладка прихована, а позначати «потрібне перемальовування» й виконувати при візиті. Це зміна поведінки (клас C), у DS-5 не включаю; питання Q11 лише для повноти.
Анімації: смуги `scaleX`, стовпчики `scaleY` (`transform-origin`), одометр `translateY`, поява `opacity`; висота розгортання (`grid-template-rows`) — виняток, що вже прийнятий ДС-планом (розд. 2) і має precedent у словнику. Стеля кількості одночасних анімацій: одометр ≈ 6 чисел × до 8 цифр = ~50 елементів із `transition: transform`, смуги днів — 31 елемент з `animation` (`dpop`); обидва в межах бюджету M2 (`DASH_MAX_*`), але при реалізації зберегти **стелю** й режим `prefers-reduced-motion` (число й графік з'являються одразу; `aria-label` одометра містить кінцеве число).

## 11. Питання до чату

- **Q1.** «≈ на день»: ділити на `N − T + 1` (з сьогодні, як у макеті: 15) чи на `N − T` (14, як у «14 днів лишилось»)? Рекомендація: з сьогодні, підпис «включно із сьогодні» не потрібен, але вирівняти «днів лишилось» на `N − T + 1`.
- **Q2.** «Необов'язкові»: усі підкатегорії з пріоритетом чи лише «Високий» і «Середній»? Макет: лише ці два рівні, з кольором Високий = зелений (інверсія до чинного червоного). Підтвердити набір і колір.
- **Q3.** Список у шторці: усі категорії (кільце топ-5 + «Інші») чи рівно ті сектори, що на кільці? «Без підкатегорії» додаємо?
- **Q4.** Відсотки від витрат замість доходу: підтверджуєте?
- **Q5.** Крапки неповних даних на плитках «Борг» і «ОЧ»: показувати (як зараз на KPI боргу) чи лише всередині шторок?
- **Q6.** Блоки без місця в макеті («Витрати/Дохід», «Динаміка боргу» KPI, «ОЧ» KPI, «Звичка місяця») прибрати остаточно?
- **Q7.** Висновки: лишити чинні п'ять (лише іконки) чи перейти на три з макета (нові формули, клас C)?
- **Q8.** Одометр (макет) замість `countStep`: схвалити; лічильники з даними для тестів лишаємо в `data-final`.
- **Q9.** Типовий місяць при рівно 3–4 місяцях: після відкидання лишається 1–2 значення; лишити як у ТЗ?
- **Q10.** Анімація довжини дуги кілець (`stroke-dasharray`): прийняти як виняток із правила «лише transform/opacity» чи робити інакше?
- **Q11.** Не рахувати `renderDashboard`, поки вкладка прихована (економія, але зміна поведінки): так чи ні? За замовчуванням ні.

## Рішення 18.11
Підтвердив Андрій (рішення чату після Кроку 0):
- **Формули:** F1 (смуга днів, різниця з темпом, округлення до 100), F2 («на той самий день»), F3 («≈ на день» = вільні / (N − T + 1), до 10 ₴, «лишилось N днів» з того самого знаменника; чисельник уточнено 18.11 після перегляду знімків: «решта» = вільні − витрачене на необов'язкове = дохід − витрати, не просто «вільні»), F4 (обов'язкові без змін, числа макета виправити), F5 (частка ОЧ), F6 («% використано» і дельта лише з `cardDeltaKnown`), F8 («≈ на рік» = 12 × типовий місяць: 5–6 місяців — без найбільшого й найменшого; 3–4 — просте середнє без відкидання; менше 3 — просте середнє з «мало даних»), F9 (відсотки від витрат).
