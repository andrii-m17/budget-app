## Пропозиції для функціональних пунктів (потрібне рішення)
- **(4) Автор-колір:** замінити розпізнавання за ім'ям на явну прив'язку користувача до кольору в `users` (поле на сервері, чат) або за порядком у родині; до того лишити як є. Ризик: зміна кольорів у Журналі.
- **(5) Ключі доходу:** міграція ключів `Зарплата <ім'я>` → нейтральні (`salary_1`, `salary_2`) з таблицею відповідності для імпорту й наявних записів; зачіпає дані двох пристроїв і Cloud (клас C, Крок 0 окремо). Запасний варіант: лишити ключі, змінити лише підписи в інтерфейсі на «ЗП 1/ЗП 2» (змінює вигляд).
- **(7) Історія git:** переписати історію не можна (правило: без `push --force`). Варіанти: (a) налаштувати GitHub «Keep my email address private» і `git config user.email` на `…@users.noreply.github.com` для нових комітів (рекомендую; не змінює історію); (b) прийняти як є (публічна поштова адреса в старих комітах уже опублікована); (c) створити новий репозиторій без історії (радикально, втрачається журнал тегів).
