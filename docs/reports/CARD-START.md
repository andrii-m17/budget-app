# CARD-START — Rev 2.32.137 (клас C; не запушено)

Рішення чату: картка показується лише з місяця `createdAt` і далі; запасних правил «найраніший запис боргу» немає; для ОЧ без змін; дат створення наявних даних не змінюємо, сервер не змінюємо.

## Зміни
- `isCardVisibleForMonth(acc, month)` (приховання + місяць `createdAt`, за локальною датою пристрою) і `isAccountHiddenForMonth(name, kind, month)` (картка до `createdAt` прихована; ОЧ лише `hiddenFrom`). Застосовано: список «Борги», підсумки картки, `debtTotalsForMonth` (дашборд), `kindHasActualForMonth`, останній запис за видом, «картки без боргу за місяць», крапки неповних даних.
- Нова картка: `createdAt` = момент створення (як було). Імпорт Excel: `createdAt` нової картки = початок найранішого імпортованого місяця її боргів (полудень 1-го числа місцевого часу), `updatedAt` = момент імпорту.
- Страховка проти приховування історії: картка **без** `createdAt` (лише локальна, ніколи не синхронізована; з Cloud `createdAt` приходить завжди) не обмежується; при старті й відновленні з бекапу такій картці `createdAt` ставиться за найранішим місяцем її боргів, інакше «зараз» (раніше завжди «зараз», що за новим правилом приховало б історію). Наявні `createdAt` не змінюються.
- На моку: 7 карток з `createdAt` травня: у квітні 0 рядків/крапок, у травні й жовтні по 7.

## Ризики
- Борги картки до місяця `createdAt` (наприклад, імпортована історія до травня) випадають зі списку, крапок і підсумків (за рішенням чату), але залишаються в даних.
- Місяць створення береться за локальною датою пристрою: `createdAt` у перші години місяця за UTC може потрапити в сусідній місяць на пристрої в іншому поясі.
- Стара логіка в інших місцях (графік динаміки боргу) бере підсумки з `debtTotalsForMonth`, тож змінюється разом.

- **Нова картка в ретроспективному місяці:** `createdAt` = момент створення, тож картка, додана під час перегляду місяця, раннього за поточний, і борг, який одразу вводять за той місяць, не з'являться у списку, поки не перейти в місяць створення. Це прямий наслідок правила; потрібне рішення чату (наприклад, `createdAt` = початок вибраного місяця при додаванні).
- Імпорт Excel для **наявної** картки не зсуває її `createdAt` назад: борги до її `createdAt` після імпорту лишаються невидимими.
- «Найближчі платежі» (`upcomingPayments`) перевіряє лише приховання, не `createdAt`: практично зачіпає тільки картку, створену у майбутньому місяці.
- Картка без `createdAt` не обмежується (усвідомлений виняток: на практиці мітку вона отримує при старті/відновленні).

## Матриця сценаріїв
| # | Сценарій | Очікувано | Перевірка |
|---|---|---|---|
| 1 | місяць до `createdAt` | картки нема в списку, без крапки, не в підсумках | unit + мок |
| 2 | місяць створення і після | видима | unit + мок |
| 3 | 7 наявних карток (created_at травня) | видимі з травня, невидимі раніше | unit + мок |
| 4 | нова картка | `createdAt` = зараз | unit (код) |
| 5 | імпорт Excel | `createdAt` = початок найранішого місяця боргів, борги видимі | unit |
| 6 | прихована для місяця | без крапки | unit |
| 7 | картка без `createdAt` | без обмеження; стемпінг за найранішим боргом | unit |
| 8 | ОЧ | без змін | unit |
