# KB-RESUME-7 · Крок 0 (без змін застосунку)

## 1. Слухачі між `kb-win-blur` і `visibilitychange hidden`
| Слухач | Що робить у проміжку | Небезпека |
|---|---|---|
| `window blur` (`kbShotCancel`, `kbWinDiag`) | лише скасовує таймер KB-SHOT і пише діагностику | нема |
| `visualViewport resize` → `updateKbSheetGeometry` | при `vvH 894`, `kbSheetNewF`, стані конвеєра animating/settled і полі у фокусі (KB-5b) — одразу `return`. Поза цими умовами (`kbSheetNewF` false, конвеєр `idle`) перераховує `--kb-h 0`, `--vv-h`, `--sheet-max-h` за повною висотою, `kbNoteKbH(0)` ігнорується (`v > 0`), у кеш/сховище висота не пишеться (лише при відкритій клавіатурі) | `--sheet-max-h` може зрости; положення не міняє |
| `visualViewport resize` (закриття, ~23350) | поле у фокусі → `kbFocusInTextField()` → вихід без дій | опускає, лише якщо фокус пішов |
| `KB_LIVE` / `kbPipeFollow` | лише при `isKeyboardOpen` → у проміжку не викликаються | нема |
| `kbVvTopCloseFollow` | лише після `exitKbSheet` на Android | нема |
| `kbCloseConfirmTimer` | у коді лише скидається, нових таймерів не ставиться | нема |
| `focusout` поля | якщо iOS зніме фокус — звичайне опускання (`closeNow`) | саме це обнуляє знімок («focusout з іншої причини») |
| `window focus` + KB-SHOT | якщо `vvH` ще повна — через 300 мс `kbResetOnBackground('win-focus')`: blur поля й звичайне закриття | це поведінка «перемикач без hidden», лишається як зараз |

Висновок: пізній `hidden` (до 3 с) нічого не опускає, `kbSheetActive` не скидається, неправильна kbH не пишеться. Факти MT-1125-1348 (шторка нерухома 321–1454 мс) це підтверджують. Якщо `hidden` не прийшов зовсім: після `window focus` спрацює KB-SHOT (за умови `vvH` повної) → звичайне закриття, як зараз; знімок скидається на `window focus` (за ТЗ), тож keep-lift не вмикається.
Ризик знімка: на самому `blur` `vvH` уже може бути 894 (одна мс із `vv-resize`). Тому знімок треба оновлювати не лише на blur, а й під час відкритої клавіатури (у `vv resize`, без читань розмітки): на blur береться останній «клавіатура відкрита».

## 2. `--sheet-lift` і анімація
Підйом — JS-нога `kbSetLift(target)` (WAAPI, клас `kb-lift-js`): тривалість `KB_MOTION_DUR` = 250 мс, крива `KB_MOTION_CURVE` = cubic-bezier(.38,.7,.125,1); старт — з поточного `--sheet-lift` (`from`). Миттєво поставити без переходу можна: `kbLiftStop()` + `kbMotionVar('--sheet-lift','0')` (CSS-перехід `transform` на `html.kb-sheet .drawer.open` вимкнено в режимі B; для режиму з переходом — зняти клас/перехід на 1 кадр). Далі `kbSetLift(lift)` дає ту саму анімацію, що й відкриття (200–350 мс, X2 виконується). Нюанс: висоту, збільшену в KB-RESUME-6 (`min-height`), у спокої шторка має «високою» → на 1–2 кадри після visible видно високу шторку внизу. Пропоную застосовувати збільшення на hidden (невидимо) і анімувати лише transform 0 → lift.
Анімація «sheet-close» на hidden не стартує, бо `exitKbSheet` не викликається (стан keep).

## 3. Сховище висот і джерело kbH
Ключ `kbHeightKey(клас пристрою|орієнтація|вид|baseH)`; `kbHeightFromStore(orient, kind)` читає localStorage. Вміст на телефоні Андрія я прочитати не можу (локальне сховище пристрою); з фактів чату: numeric 389, text 388–389, тож записи для обох видів очікуються. Зараз у KB-RESUME-6 kbH = `kbHeightFromStore(orient, kbSheetCacheKind || kbCacheKindForField(a))`, інакше `baseVh − vv.height`. На hidden `vv.height` уже 894 → запасний варіант дає 0 → план пропускається, а `kbSheetCacheKind` — вид останньої сесії шторки, не обов'язково вид поля. Тому потрібен знімок: вид поля через `kbCacheKindForField(поле)` на blur і kbH з нього.

## 4. Блокування дотиків
`pointer-events:none` на шторці не підходить: дотик «провалюється» на елементи під нею (фон, кнопки, закриття по підложці). Пропоную прозорий щит `position:fixed; inset:0` вище шторки (z-index над 91), який існує лише від visible до кінця анімації + 50 мс (страховка 500 мс) і лише ловить touchstart (пасивний слухач, без preventDefault, лічильник `touchDuringLift`). Дотик, що почався на щиті, нічого не фокусує; наступний дотик іде нативно по полю (щит уже знято), тож нативний фокус не ламається. Ризик: щит перехоплює й дотик поза полем (тягнення, закриття) — на ≤ 300 мс; це прийнятно за ТЗ (дотик рахується).

## План змін
1. Чиста `kbKeepEntryBy({kbOpenNow, snapAgeMs, sameDrawer, drawerOpen, fieldConnected, sameOrientation, lift})` → `now | blur-snap | none` (межа 3000 мс: ≤ 2999 так, ≥ 3000 ні).
2. Знімок: оновлюється у vv resize при відкритій клавіатурі й на blur; скидання за переліком ТЗ.
3. Чисті `kbKeepPickKbH` (store-kind → store-text → snapshot) і план підйому.
4. `kbKeepEnter` на hidden: blur поля, миттєвий спокій, збільшена висота (невидима), стан зберегти.
5. visible: перевірка → через 1–2 кадри `kbSetLift`; після завершення — `kb-resume-lift` (`from`, `to`, `ms`, `frames`, `jumpMax`); щит.
6. Охоронець для `kbNoteKbH`, `kbVvTopCloseFollow`, `KB_LIVE` у стані keep і під час підйому; нові ключі самописця (без «text»), тести за ТЗ.

## Ризики
- Стан гонки blur/vv-resize (див. п. 1) — знімок у vv resize.
- «Висока шторка в спокої» 1–2 кадри після visible (п. 2) — мінімізується порядком дій.
- Щит перехоплює дотики ≤ 300 мс.
- Перемикач без hidden: поведінка як зараз (закриття KB-SHOT) — свідомо.
- Файл-ключ `liftExtra` уже замінено на `liftMore` через тест приватності; нові ключі перевіряти тим самим тестом (уникати підрядків text/name/value тощо).
