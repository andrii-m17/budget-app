# Протокол економії ресурсів (чат · Claude Code · Notion)

Принцип: вартість росте з довжиною контексту, який перечитується щоразу. Тому: короткі розмови, короткі повідомлення, стабільне в кешованих файлах, динамічне в Notion.

## 1. Розмова в чаті
| Ситуація | Дія |
|---|---|
| Задачу завершено (звіт прийнято) | **нова розмова** |
| Понад ≈ 25 реплік АБО був великий результат (архів, кілька макетів, багато пошуків) | нова розмова |
| З'явилось стиснення/«summarized» | одразу нова розмова (деталі вже втрачені) |
| Дрібне питання | нова розмова, звичайна модель, низькі зусилля |
| Нова розмова | перша репліка: резюме ≤ 12 рядків + «візьми задачу X» |

## 2. Куди класти інформацію
| Що | Куди |
|---|---|
| ТЗ класу A (≤ ≈ 15 рядків) | вставити в Claude Code напряму, без Notion |
| ТЗ B/C і звіти | Notion; у чаті лише «звіт готовий» |
| Стабільні документи (STATUS, WORKFLOW, SCENARIOS, UI_PATTERNS) | репозиторій + файли Project (кешуються) |
| Логи, дані, розміри | чат читає з Supabase запитом; нічого не вставляти |
| Скріншоти | лише потрібний фрагмент, лише коли без нього не обійтись |
| Правила | навички й критичні правила, не в кожному ТЗ |

## 3. Claude Code
| Ситуація | Дія |
|---|---|
| Нова задача з Notion | `/clear` (нова сесія) |
| Довга задача класу C, контекст ≈ 50–60% (`/context`) | запиши ключове в Notion, потім `/compact` з інструкцією «зберегти рішення, зміни, відкриті питання» |
| Не користуєшся Supabase MCP | вимкнути через `/mcp` |
| Рецензія | субагент `spec-reviewer` лише для B/C |
| Раз на тиждень | `/usage`: частка навичок, субагентів, MCP |

## 4. Модель і зусилля
Звичайна модель і зусилля: макети за готовим шаблоном, приймання звітів, дрібні правки, ТЗ класу A. Вища: дизайн і архітектура, дані й синхронізація, безпека, аналіз логів. Після складної задачі повернути звичайну.

## 5. Бюджет моїх відповідей (чат)
Звичайна відповідь до ≈ 250 слів; великий результат до ≈ 600. Без повторення контексту й списків «що чекає» у кожній репліці (вони в Notion/STATUS). Не більше 3 пунктів «Що від вас». Один варіант макета з рекомендацією, інші лише на прохання. Пошук в інтернеті лише коли факт міг змінитись. SQL-вибірки з LIMIT. Не повторювати повний текст ТЗ у відповіді, якщо він у Notion.

## 6. Конектори
У розмові без потреби вимкнути Notion і Supabase («Search and tools»).
