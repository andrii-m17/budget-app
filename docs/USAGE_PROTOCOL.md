# Протокол економії ресурсів (чат · Claude Code)

Принцип: вартість росте з довжиною контексту, який перечитується щоразу. Тому: короткі розмови, короткі повідомлення, стабільне в кешованих файлах, повні звіти в репозиторії (`docs/reports/`), чату лише короткий звіт.

## 1. Розмова в чаті
| Ситуація | Дія |
|---|---|
| Задачу завершено (звіт прийнято) | **нова розмова** |
| Понад ≈ 25 реплік АБО був великий результат (архів, кілька макетів, багато пошуків) | нова розмова |
| З'явилось стиснення/«summarized» | одразу нова розмова (деталі вже втрачені) |
| Дрібне питання | нова розмова, звичайна модель, низькі зусилля |
| Нова розмова | перша репліка: резюме ≤ 12 рядків + «візьми задачу X» |

## 2. Куди класти інформацію
| Що | Куди |
|---|---|
| ТЗ класу A (≤ ≈ 15 рядків) | вставити в Claude Code напряму |
| ТЗ B/C | у відповіді чату повністю; Користувач А вставляє в Claude Code |
| Звіти | повний у `docs/reports/<код>.md`; чату стільки, скільки потрібно для рішення, без повторення контексту |
| Стабільні документи (STATUS, WORKFLOW, SCENARIOS, UI_PATTERNS) | репозиторій + файли Project (кешуються) |
| Логи, дані, розміри | чат читає з Supabase запитом; нічого не вставляти |
| Скріншоти | лише потрібний фрагмент, лише коли без нього не обійтись |
| Правила | навички й критичні правила, не в кожному ТЗ |

## 3. Claude Code
| Ситуація | Дія |
|---|---|
| Нова задача | `/clear` (нова сесія) |
| Довга задача класу C, контекст ≈ 50–60% (`/context`) | запиши ключове в `docs/reports/<код>.md`, потім `/compact` з інструкцією «зберегти рішення, зміни, відкриті питання» |
| Не користуєшся Supabase MCP | вимкнути через `/mcp` |
| Рецензія | субагент `spec-reviewer` лише для B/C |
| Раз на тиждень | `/usage`: частка навичок, субагентів, MCP |

## 4. Модель і зусилля
Звичайна модель і зусилля: макети за готовим шаблоном, приймання звітів, дрібні правки, ТЗ класу A. Вища: дизайн і архітектура, дані й синхронізація, безпека, аналіз логів. Після складної задачі повернути звичайну.

## 5. Бюджет моїх відповідей (чат)
Відповідь: стільки, скільки потрібно для рішення, без повторення контексту. Без повторення контексту й списків «що чекає» у кожній репліці (вони в STATUS). Не більше 3 пунктів «Що від вас». Один варіант макета з рекомендацією, інші лише на прохання. Пошук в інтернеті лише коли факт міг змінитись. SQL-вибірки з LIMIT. Не повторювати повний текст ТЗ у відповіді, якщо він уже в репозиторії.

## 6. Конектори
У розмові без потреби вимкнути Supabase (Notion для звітів не потрібен) («Search and tools»).

## 7. Перевірка за ризиком (знімки й субагенти)
Клас A: лише `node --test`. Клас B: один знімок «до/після» зачепленого екрана (темна тема, 390 pt; «0» пікселів лише для змін, що мають бути невидимими) і один `spec-reviewer`. Клас C: тести й цільові сценарії на моку, один `spec-reviewer`, знімки лише якщо змінюється вигляд. `apple-review` і `apple-pwa-design` лише на запит. Знімки: один ланцюжок за раз, власна тека з міткою часу, готовність за кодом завершення, ≤ 60 с на знімок і ≤ 3 хв на крок, одна повторна спроба невдалого знімка, далі йти; двічі поспіль невдало: запропонувати вимкнути. Таймери стосуються лише знімків (не автотестів, збірки, гачка пушу). Скрипти порівняння запускаються лише з `--run`. Деталі: `docs/WORKFLOW.md`.
