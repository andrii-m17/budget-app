# Матриця сценаріїв

Більшість наших помилок проявлялась у станах, про які не подумали заздалегідь: порожній список, одна група, коротший місяць, відкритий застосунок замість фонового, preview з реальною сесією. Матриця змушує подумати про них до коду.

## Як
1. Відкрий `docs/SCENARIOS.md`, візьми «Мінімум за типом зміни» й додай осі, що стосуються задачі.
2. Для кожного сценарію запиши очікувану поведінку **до** реалізації.
3. Для кожного рядка вкажи спосіб перевірки: `unit` (node --test), `e2e` (Playwright + fixture), `preview` (вручну), `iPhone` (пункт у `qa.json`).
4. Рядки без способу перевірки: або додай тест, або винеси в «Не перевірено / ризики» звіту.

## Формат (вставити в Крок 0 і у звіт)
```
## Матриця сценаріїв
| # | Сценарій | Очікувано | Перевірка |
|---|---|---|---|
| 1 | Порожній список | порожній стан із кнопкою «Додати» й підписом | e2e: fixture empty |
| 2 | 5 000 витрат | відкриття < 1,5 с, без підвисань прокрутки | e2e: fixture large |
| 3 | iPad альбом | дві колонки не ламаються | e2e: iPad landscape |
```

## Правила
- Не менше 8 рядків для класу C, не менше 5 для B.
- Якщо сценарій виявляє суперечність у ТЗ, зупинись (див. `step0-audit`).
