# UI за макетом

## Джерела істини (за пріоритетом)
1. Макет із промту (екрани названі в промті).
2. `docs/UI_PATTERNS.md` (виміряні компоненти застосунку).
3. Текст промту. **Якщо текст суперечить макету, обирай макет і познач це у «Відхиленнях»** (був випадок: у тексті «два рядки», на макеті три).

Якщо макет суперечить домінантному патерну застосунку (контейнер, радіус, положення, кнопки), **зупинись** і опиши розбіжність у звіті.

## Реалізація
- Кольори й рух лише з токенів `--ui-*` і `--motion-*`; жодних «магічних» кольорів.
- Іконки лише SVG, без емодзі (емодзі допустимі лише як дані користувача, наприклад у назвах категорій).
- Мінімальний текст 11 пт; зона дотику ≥ 44 пт; контраст ≥ 4,5:1 в обох темах.
- Реакція на натискання M1 для кожного інтерактивного елемента; анімація лише `transform`/`opacity`, крім явно погоджених винятків; `prefers-reduced-motion`.
- Динамічно створені сегменти й елементи підключай до тих самих механізмів (наприклад `initSegments()`).
- Фокус при відкритті шторки на контейнері, не на полі (див. `ios-keyboard-safety`).

## Перевірка
1. Скріншоти «після»: темна й світла теми, ширина 390 і 440 → `docs/ui/<задача>-<тема>-<ширина>.png`.
2. Виміряй обчислені стилі ключових елементів і порівняй з макетом (таблиця «макет / реалізація»).
3. Перевір стани: порожній, один елемент, багато, довгий текст, помилка.
4. Після масових замін CSS шукай дублікати блоків і «мертві» правила.
5. Онови `docs/UI_PATTERNS.md`, якщо з'явився новий компонент.
