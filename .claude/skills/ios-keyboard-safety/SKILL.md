# Безпека клавіатури iOS

Клавіатурна логіка найкрихкіша частина застосунку: її налагоджували десятками ревізій за логами з iPhone. Preview її не відтворює.

## Що не чіпати без окремої задачі класу C
Проміжне поле (`kb-focus-proxy`), стрілки між полями, курсор, `kb-*`-класи, підйом шторки, `kbSheetHostOf` (обслуговує `.drawer, .app-modal`), Баг 1, safe-area Багу 1a.

## Відомі пастки
- Клавіатурні функції живуть усередині `initApp`; глобальний код викликає їх лише через безпечні обгортки (`typeof` або `focusCardFieldSafe`). Інакше на iPhone тихий `ReferenceError`, а юніт-тести його не бачать.
- Фокус при відкритті шторки на контейнері (`tabindex=-1`), не на полі, інакше клавіатура вискакує без дотику й перекриває шторку.
- Шторки створюй у `.drawer`, а не в новому контейнері: так вони автоматично отримують клавіатурну логіку.

## Перевірка
1. Клавіатурні тести зелені.
2. У preview лише логіка й відсутність винятків у консолі; поведінку клавіатури не стверджуй.
3. Для користувача: кроки в «Сервіс» → «Перевірки» і протокол запису діагностики: «Сервіс» → «Діагностика» → «Записати діагностику» зі сценарієм `<код задачі>`, по два відкриття кожної зачепленої шторки, «Мітка» при дивній поведінці, «Надіслати лог». Аналіз логу робить чат.
