# Звіт про задачу

Звіт читає чат (приймає роботу) і користувач (вирішує й перевіряє на iPhone). Однаковий формат скорочує уточнення. Пиши коротко: факти, числа, без переказу ТЗ.

## Шаблон (завжди цей порядок)
```
## Підсумок
1–3 речення: що зроблено або чому зупинився.

## Ревізії
| Rev | Коміт | Що |
|---|---|---|

## Перевірено
Як саме і чим (тести: N пройшли / M усього; preview; вимірювання з числами; скріншоти: шляхи файлів).

## Не перевірено / ризики
Чесно: що не вдалося перевірити, де можлива регресія.

## Відхилення від ТЗ
Що зроблено інакше й чому. Якщо ТЗ суперечило макету: що обрано.

## Запити до чату
Серверні зміни, рішення, яких бракує (або «немає»).

## Перевірка на iPhone
Конкретні кроки й очікування (також додано в qa.json).

## STATUS
+ Додано: ...
✓ Закрито: ...
⏳ Чекає: ...

Сесія: /clear   (або: /compact (збережено в Notion), якщо клас C посередині і контекст ≈ 50–60% за /context)
```

## Правила
- Не нагадуй пунктів із розділу «Закрито» в `docs/STATUS.md`.
- Числа замість оцінок («висота 139 пт», «запитів 55 → 5»).
- Якщо зупинився (розбіжність, клас C): секції «Ревізії» й «Перевірено» можуть бути порожніми, але «Запити до чату» обов'язкові.
- Кожен звіт закінчується рядком «Сесія: /clear» (задачу завершено) або «Сесія: /compact (збережено в Notion)» (клас C посередині, контекст ≈ 50–60%).
- Не вигадуй успіх: якщо не перевіряв на справжньому пристрої, так і пиши.
