# Нове поле вводу

iOS показує панель «Автозаповнити контакт», якщо вважає поле контактним. Ми двічі ловили це на полях із «небезпечними» ідентифікаторами й підписами, тому правила суворі.

## Обов'язково
- `id` абстрактний (`fldstr4`, `fldmono2`), без підрядків `name`, `phone`, `tel`, `mail`, `addr`, `user`, `login`, `first`, `last`, `fio`, `contact`; те саме для атрибута `name`.
- Підписи й підказки без слів «ім'я», «телефон», «пошта», «адреса», «контакт».
- `autocomplete="off"`, `autocorrect="off"`, `spellcheck="false"`; потрібний `inputmode` і `enterkeyhint`.
- Створюй через спільну функцію полів, яка враховує активний варіант тесту `autofill-guard`.
- Додай `id` у `KNOWN_TEXT_FIELD_IDS` (охоронний тест має пройти).
- Значення в HTML лише через `escapeAttr`/`escapeHtml`.
- Цілі гривні: суми парсяться й перевіряються як цілі (`normalizeAmount`).
- Поле в шторці: переконайся, що клавіатурний модуль його обслуговує (див. `ios-keyboard-safety`).
- Для `select`: прозорий `select` поверх рядка, значення малюється окремо (інакше iOS обрізає текст).

## Тести
Охоронний тест ідентифікаторів, тест парсингу значення, тест екранування.
