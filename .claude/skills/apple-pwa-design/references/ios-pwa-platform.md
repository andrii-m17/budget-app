# Платформа iOS PWA (WebKit)

Перевірено 21.10.2026 за webkit.org, MDN, WebKit Bugzilla. **[П]** підтверджено; **[Н]** ні.

## Режим застосунку з головного екрана
- З iOS/iPadOS 26 кожен сайт, доданий на Home Screen, за замовчуванням відкривається як веб-застосунок (користувач може вимкнути «Open as Web App»); маніфест уже не обов'язковий, але його переваги (іконки) діють [П webkit.org Safari 26 beta/26.0].
- Раніше: `apple-mobile-web-app-capable` (iPhone OS 2.1), маніфест `display` (iOS 11.4) [П]. Для web push `display` має бути `standalone` або `fullscreen`; `id` маніфесту разом з іменем ідентифікує застосунок для Focus [П webkit.org 13878].
- Іконки: `apple-touch-icon` має перевагу над іконками маніфесту (коли є обидва); маніфестні іконки підтримано з 15.4 [П]. SVG-іконки підтримано в Safari 26 [П].

## Безпечні зони й viewport
- `env(safe-area-inset-*)` дають відступ від краю до безпечної зони; 0 для прямокутного вікна без панелей [П MDN env]. Потрібен `viewport-fit=cover` у meta viewport, щоб вміст ішов під системні панелі, а inset-и давали значення [Н: у прочитаній MDN-сторінці не згадано; підтверджують розробницькі блоги й баг-репорти].
- **iOS 26.1:** Home Screen застосунки перестали малювати вміст під статус-баром, `safe-area-inset-top` повертає 0 замість ≈ 44 pt (WebKit Bugzilla 301994). Стан на 15.10.2026: REOPENED; користувачі повідомляли про виправлення в 26.2, але далі баг відтворюється на 26.5.2 і iOS 27 beta [П bugs.webkit.org/show_bug.cgi?id=301994]. Тому «виправлені в 26.2» **не підтверджено**: не покладатись.
- Окремий баг: у Safari 26.2 фон статус-бару замінюється тінню від фону сторінки при м'якій навігації (SPA, свайп назад) [П за результатом пошуку Bugzilla 305546, статус NEW; сторінку не відкривав: Н].
- Bug 301108 (REGRESSION iOS 26): `viewport-fit=cover`/`height=device-height` працюють некоректно; статус NEW [П]. Фіксований непрозорий заголовок: вміст більше не просвічує (за коментарем) і тема заголовка Liquid Glass не оновлюється при перемиканні dark/light без перезавантаження [П коментарі].
- `theme-color` у iOS 26: колір беруть з тла (за вашим завданням); у MDN це лише «пропозиція» з `media` для light/dark; підтримка Safari в прочитаній сторінці не названа [П/Н]. Офіційного підтвердження поведінки з Liquid Glass немає [Н]. Проєктне обмеження: `status-bar-style: default` (`docs/PLATFORM_LIMITS.md`).
- `dvh/svh/lvh`: dvh змінюється з панелями браузера й може давати зсуви макета й втрати продуктивності; `vh` дорівнює `lvh` [П MDN]. Версія Safari 15.4 для них [Н: з пам'яті, у MDN-вибірці немає].

## Поля вводу
- Safari на iPhone масштабує сторінку при фокусі на полі зі шрифтом < 16 px [Н: офіційного опису WebKit не знайдено, лише блоги й форуми]. Тримай ≥ 16 px. `maximum-scale=1`/`user-scalable=no` шкодять доступності; на iOS ≥ 10 його ігнорують [Н].
- Правила `id` полів (без `name`, `phone` тощо): `docs/PLATFORM_LIMITS.md`.

## Сховище [П webkit.org 14403, 10218]
- Квоти (Safari 17+): Safari і Home Screen застосунки до 60 % диска на origin і 80 % загалом; інші застосунки 15 % / 20 % [П]. `navigator.storage.persist()` задовольняється за евристикою, зокрема для Home Screen застосунків; режим за замовчуванням best-effort [П].
- **7-денне правило ITP** (видалення скриптового сховища після 7 днів використання Safari без взаємодії) **не застосовується до Home Screen застосунків**: вони мають власний лічильник днів використання, який скидається використанням; WebKit не має наміру видаляти дані першої сторони у веб-застосунках, а втрата це «серйозна помилка» [П webkit.org 10218].
- Але Declarative Web Push описує сценарій «service worker видалено користувачем або ITP» [П 16535]: для сайтів у Safari, не для Home Screen. Для нас важлива наша логіка надгробків і повної звірки, не сам iOS.

## Web Push (вимоги) [П webkit.org 13878, MDN]
- З iOS/iPadOS 16.4, лише для застосунків з Home Screen; дозвіл запитується тільки у відповідь на жест користувача; сповіщення на Lock Screen, у Центрі й на Apple Watch; Focus підтримується; Badging API (`setAppBadge`) [П].
- Сервер дозволяє `*.push.apple.com`; членство в Apple Developer Program не потрібне [П].
- Активний service worker потрібен для звичайного push; подія `push` викликає `showNotification()`; `pushsubscriptionchange` повідомляє про недійсну підписку [П MDN].
- Silent push (без показу) і штрафи/відкликання: у прочитаних джерелах прямо не описано [Н]; HIG і практика: кожен push має показати сповіщення.
