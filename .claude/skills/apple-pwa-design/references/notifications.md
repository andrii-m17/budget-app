# Сповіщення

Джерела: HIG Notifications (через JSON-версію сторінки), webkit.org (13878 Web Push, 16535 Declarative Web Push, 16574 Safari 18.4), MDN Push API. Перевірено 21.10.2026.

## HIG [П]
- Потрібна згода до першого сповіщення; користувач сам обирає стилі й час у Налаштуваннях.
- Зміст: стисло й інформативно; короткий заголовок лише якщо додає контекст (title-case без крапки в кінці); повні речення; не обрізай (систему це зробить); дай загальний текст на випадок прихованих прев'ю; не повторюй назву застосунку й іконку (їх показує система); без чутливих даних; звук лише доповнює; не кажи «зроби X у застосунку»: давай дії або нічого; для помилок alert, не сповіщення.
- Частота: не дублюй про одне й те саме, навіть без реакції; надлишок засмічує Центр і веде до вимкнення. Коли застосунок на екрані, не шли сповіщення: онови UI (бейдж, нові дані).
- Дії: до 4 кнопок; короткі, описують результат, без імені застосунку; не додавай дію «лише відкрити»; перевага недеструктивним; деструктивна з контекстом.
- Рівні переривання (passive/active/time-sensitive/critical) HIG-сторінка Notifications не описує [П]; для Web Push на iOS керування рівнями недоступне [Н].

## Web Push на iOS [П webkit.org 13878]
- З 16.4, лише застосунки з головного екрана; запит дозволу після жесту; відображення на Lock Screen, в Центрі, на Watch; Focus; Badging API.
- Подія `push` у service worker, `showNotification()`; `pushsubscriptionchange`; ендпоінт це «capability URL» (секрет) [П MDN].
- Практика проєкту: показувати кожен push негайно; журнал після показу (Rev 2.32.101).

## Declarative Web Push (iOS 18.4+) [П webkit.org 16535, 16574]
Оцінка (лише пропозиція, не впроваджено):
- **Мінімальна версія:** iOS/iPadOS 18.4 (Safari 18.4), «для веб-застосунків, доданих на головний екран» [П 16574]. На macOS 15.5 beta тестувалось [П].
- **Підписка:** `pushManager.subscribe()` з `userVisibleOnly: true` і `applicationServerKey` із вікна, service worker не обов'язковий; якщо є service worker з областю «/», підписка спільна [П].
- **Формат payload (JSON):** верхній `"web_push": 8030` (обов'язково, вмикає декларативну обробку); `"notification"` об'єкт: `title` (обов'язковий, непорожній), `navigate` (обов'язковий URL), інші поля `NotificationOptions` (`lang`, `dir`, `body`, `silent`, `app_badge` та ін.) [П]. MIME-тип і заголовки сторінка не вказує [Н]; специфікація: чернетка Push API, формат у ній.
- **Сервер:** надсилання те саме (Web Push + VAPID); тіло має бути в декларативному форматі. Наша `send-push-notification` шле `{title, body, data:{type, tag, batch_ts, push_id, …}}`: довелось би загорнути це в `web_push: 8030` і `notification {title, body, navigate, …}`; куди класти власні `data` і `tag`, сторінка 16535 не пояснює (повний список полів `NotificationOptions` не наведено) [Н].
- **Старі iOS (16.4–18.3):** повідомлення в декларативному форматі зворотно сумісні: браузер без підтримки обробляє їх імперативно через JS (наш `sw.js` мусить розуміти новий формат payload: брати `notification.title`/`body`) [П]. Тобто потрібні обидві гілки одного payload.
- **З service worker:** подія `push` усе одно диспатчиться з пропонованим сповіщенням; якщо воркер не показав заміну вчасно, браузер показує пропоноване [П]. Це робить декларативний шлях запасним для зависання воркера (наш симптом NOTIF-3).
- **Тап:** браузер сам переходить на `navigate` без JS [П]. Наші типи з маршрутизацією в застосунку (`handlePushAction`, `pendingAction` в IndexedDB, `batchTs`) довелось би виражати через URL-параметри (`?pushAction=…&batchTs=…`: механізм у застосунку вже є [за кодом]).
- **Що втрачаємо:** журнал воркера «Отримано на цьому пристрої» (воркер не виконується, якщо не змінює сповіщення) і наш «розширений» журнал подій; `renotify`/`tag` керування залежить від полів NotificationOptions [Н]; підтвердження показу з пристрою (`push_ack`) неможливе без воркера. Кореляція лише через сервер (`push_sent_log`).
- **Обмеження:** кожне повідомлення має показати сповіщення; тихий push заборонений; без воркера вміст не змінити (локальні дані в тексті недоступні) [П].
- **Статус:** сторінка описувала це як готове до експериментів [П 16535]; у 16574 вказано доступним у 18.4 [П]. Стійкість у продукційній експлуатації не перевірена [Н].
